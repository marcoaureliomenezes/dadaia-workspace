Summary

PASS Both test cases green. The orphan-detection script (tests/scripts/check_skill_orphans.py) now accepts a DADAIA_WORKSPACE_ROOT environment variable to override the hard-coded path derived from __file__. The self-test at tests/unit/scripts/test_check_skill_orphans.py seeds a temporary workspace tree, drives the script as a subprocess, and asserts the two required behaviours: orphan detection (exit 1, orphan name in stderr) and clean run (exit 0, empty output).

Fixture design

The _seed_workspace(tmp_path, agent_skills) helper creates the minimal fake tree inside pytest's tmp_path fixture (never touching the real workspace):

  • <tmp>/dadaia_workspace/public/skills/__wired_skill/SKILL.md — always created; wired or not depending on agent_skills.
  • <tmp>/dadaia_workspace/public/skills/__orphan_skill/SKILL.md — always created; initially NOT listed in the agent.
  • <tmp>/dadaia_workspace/public/agents/fake-agent.md — YAML frontmatter with skills: list controlled per test case.

Test case 1 passes agent_skills=["__wired_skill"] so __orphan_skill is unreferenced. Test case 2 passes agent_skills=["__wired_skill", "__orphan_skill"] so all skills are wired.

Subprocess invocation pattern

The script is invoked via subprocess.run with capture_output=True and the env var DADAIA_WORKSPACE_ROOT pointing to tmp_path. This is safer than monkeypatch.chdir because it does not mutate the process-level working directory, making the tests safe to run in parallel. 

result = subprocess.run(
    [sys.executable, str(_SCRIPT)],
    capture_output=True,
    text=True,
    env={"DADAIA_WORKSPACE_ROOT": str(tmp_path), "PATH": str(Path(sys.executable).parent)},
)

The 1-line change to the script (os.environ.get("DADAIA_WORKSPACE_ROOT", ...)) is backward-compatible: absent the env var, the script resolves _ROOT from __file__ exactly as before.

CI hook note

Because tests/unit/scripts/test_check_skill_orphans.py is collected by pytest under the standard tests/ tree, the CI suite picks it up automatically. This satisfies the TASKS note: "CI hook (pytest collection) catches future orphans." No separate CI step is needed.
