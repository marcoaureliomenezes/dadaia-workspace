RCA — dev-server-registry visibility

Author: software-engineer (claude-main) · Created: 2026-05-17T20:00:00Z · Context: dadaia-workspace · Release: v0.1.1

Symptom

Operador rodou um dev server para o projeto redacted-slug e tentou registrá-lo via dadaia server register. Apesar de "ações drásticas" (re-execuções, re-registros manuais), o servidor não apareceu nem em dadaia server list nem no panel. Somente o redacted-slug (port 3968) — registrado por outro agente concorrente — ficou visível.

A BLOCKER cli/commands/server.py:26-30
(copy in cli/commands/panel.py:24-29)		 _resolve_workspace() anda para cima de cwd e retorna o primeiro diretório com .dadaia/. Mas 4 sub-repos (repos/redacted-slug, repos/redacted-slug, repos/dadaia-workspace, repos/workflow-tools) têm .dadaia/ próprio sem states/. Cwd dentro de qualquer sub-repo → resolver retorna o sub-repo → _guard_initialized raises WorkspaceNotInitializedError → CLI exibe "Workspace not initialized" e aborta. B HIGH infrastructure/json_server_registry_store.py:13-17, 39-48 _load() chama json.load(f) sem try/except. _from_dict(d) exige 4 chaves obrigatórias (port, project, reserved_at, expires_at) sem fallback. C HIGH core/protocols/process_probe.py:14-19 OsProcessProbe.is_pid_alive trata PermissionError igual a ProcessLookupError — ambos retornam False. PIDs root-owned (e.g. docker-proxy do redacted-slug-dev container) ficam marcados stale. ServerRegistryService._sweep() roda em cada register() e deleta entries stale. Resultado: registrar uma porta nova de qualquer projeto deleta acidentalmente entries de portas root-owned.
D MEDIUM (gap estrutural) (registry contract) Registry é push-only: agentes que sobem python -m http.server sem chamar dadaia server register produzem orphans invisíveis ao panel. Nenhum mecanismo de reconciliação existe — dadaia server clean só limpa entries stale registradas. Skill dev-server-registry/SKILL.md:17 diz "Never start a server without registering its port first" mas é texto, não enforcement.

Reproduction (commands operator can run)

Bug A reproduction

cd /home/marco/workspace/dadaia/repos/redacted-slug
dadaia server list
# → "Error: Workspace not initialized. Run dadaia init first."
# Observed because repos/redacted-slug/.dadaia/ exists (no states/) and the resolver
# walks up and stops there before reaching the workspace root.

Bug B reproduction

cp .dadaia/states/server_registry.json /tmp/backup.json
echo '{"entries": [{}]}' > .dadaia/states/server_registry.json
dadaia server list
# → KeyError raised, registry inacessível
# Restore: cp /tmp/backup.json .dadaia/states/server_registry.json

Bug C reproduction

python -c "import os; os.kill(1, 0)" || echo "PID 1 marked dead (incorrectly)"
# As non-root user: os.kill(1, 0) raises PermissionError which the probe
# treats as ProcessLookupError → entry deleted by _sweep().

Gap D reproduction

python -m http.server 9999 --bind 127.0.0.1 &
dadaia server list
# → port 9999 nowhere; panel /api/servers returns empty group; no scan command exists.

Recommendation

Promote to hotfix release v0.1.1 (patches dadaia-workspace-panel-v1), HIGH severity, scope:

  1. Fix A: Centralize resolve_workspace_root() in core/workspace_resolver.py; require .dadaia/states/spec_contexts.json, not just .dadaia/. Replace duplicates in server.py + panel.py.
  2. Fix B: Skip-and-log discipline in JsonServerRegistryStore. Per-entry try/except. Never raise on malformed input.
  3. Fix C: OsProcessProbe.is_pid_alive treats PermissionError as alive (unprobable, not dead). Documented trade-off: false-positive better than false-negative.
  4. Fix D: New dadaia server scan CLI subcommand (read-only) + panel "Unregistered listeners" section with LAN-exposed warning badge.

Acceptance + 12 observable criteria specified in specs/releases/v0.1.1/SPEC.md. PLAN.md ordering: 6 phases, fresh agent per phase, TDD discipline.

Trade-offs accepted

  • PermissionError → alive: false-positive (entry survives even when PID died but is unprobable) is preferable to false-negative (entry deleted prematurely). TTL of 8h is the secondary cleanup signal.
  • Scan parses ss -tlnp: linux-only. macOS/Windows ficam sem feature. Aceitável: dadaia-workspace é Linux-only por design.
  • Centralized resolver breaks "each CLI has its own helper" pattern: net positive — 1 lugar para corrigir vs. N cópias divergindo.
  • "Hotfix" includes new feature (scan + UI): tipicamente seria MINOR semver, não PATCH. Aceitável porque scan + UI são partes integrais da observabilidade do fix — sem elas, bugs A/B/C continuam não-observáveis para o operador.
