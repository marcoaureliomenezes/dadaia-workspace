Softening rationale (MissingTierError to default+warn)

The prior session made the reader strict: any agent file missing tier: would raise MissingTierError and be skipped. This caused integration tests to fail because the staged content at .dadaia/agentic/agents/*.md is an older projection that may predate the tier: field addition (the stage command targets the workspace-root .dadaia/, not the repo-local one, due to workspace resolver behaviour).

The pragmatic fix:

  • Missing tier: → default to 3 (leaf specialist) and emit a sys.stderr.write warning so the operator sees it in logs but the agent is not lost.
  • Present but invalid tier: (non-integer or outside {1,2,3}) → still raises MissingTierError, causing the agent to be skipped. This catches typos loudly.

This produces tolerant behaviour for stale stage files while failing hard on configuration errors.
