ADR-CX-001 — Runtime-scoped public asset layout

Decisão: Codex-only assets vivem em dadaia_workspace/public/runtime/codex/.
Razão: Único layout que torna isolamento verificável por filesystem boundary sem naming convention frágil. NFR2 e NFR4 satisfeitas estruturalmente. Doctor pode verificar por path.
Impacto: _install_codex() ganha novo branch para ler de public/runtime/codex/. Shared assets em public/skills/ não mudam.

ADR-CX-002 — Codex plugin/skill projection format

Decisão: Sem plugins nativos Codex. Codex consome apenas [skills] paths = [".agents/skills"].
Razão: Respondido via inspeção — nenhum .codex/plugins/ existe em nenhuma instalação; _install_codex() nunca cria um; config.toml não tem seção [plugins]. Projetar violaria NFR4.
Impacto: Nenhuma mudança no pipeline de plugins.

ADR-CX-003 — Shared skill vs Codex-only adapter classification

Decisão: public/skills/<name>/ = shared (Claude + Codex + OpenCode). public/runtime/codex/<name>/ = Codex-only. Sem overrides dentro do shared. Doctor verifica que runtime/codex/ nunca vaza para .claude/ ou .opencode/.
Razão: Consequência direta de ADR-CX-001. Boundary por path elimina ambiguidade.
Impacto: Doctor ganha verificação de leak cross-runtime para assets em runtime/codex/.

ADR-CX-004 — Null-regression methodology

Decisão: SHA snapshot pytest. Fixture hasha .claude/** e .opencode/** antes e depois de install --target codex; qualquer diferença = falha de teste.
Razão: Simples, direto, não requer extensão do doctor para pilot. D-CX-6 pode ser adicionado em follow-up se padrão se repetir.
Impacto: Novo test file em tests/unit/infrastructure/test_codex_null_regression.py.
