PR4-17 — Tier-Aware Agent Cards: Design Specification

Brief

The dadaia panel Agents tab currently renders all 16 agent cards with an identical 1px solid #dddddd border and no tier differentiation. This flattens the orchestration topology — a user cannot distinguish T1 orchestrators from T3 leaf specialists at a glance. PR4-17 resolves this by: (a) bumping the default .agent-card border to 2px; (b) adding a 4px left accent stripe colour-coded per tier via data-tier attribute selectors; and (c) defining nine new CSS custom properties (3 palettes × 3 tiers) with WCAG 2.2 AA contrast verified against each palette's card background. The tier label text ("T1 Orchestrator" etc.) visible in the operator's approved mockup is included as a new .agent-card__tier-label element so the visual signal is redundant (colour + text), satisfying WCAG 1.4.1 (colour not sole differentiator).

Visual Hierarchy Findings

IMPROVEMENT No orchestration topology signal

Observation: All 16 cards share identical border weight and colour. The agents tab reads as a flat alphabetical list, not an orchestration hierarchy. The most critical agents (project-manager, project-auditor) are visually identical to leaf specialists.

Severity: Improvement (not a WCAG blocker, but a core product usability gap per SPEC §1).

Fix: 4px left tier accent stripe + tier-label text as specified below.

IMPROVEMENT 1px border too thin for card delineation

Observation: border: 1px solid #dddddd on a white surface background creates insufficient separation between cards at small viewport widths or under bright ambient light. The operator's approved direction explicitly bumps to 2px.

Severity: Improvement. Passes 1.4.11 at 1px (contrast of border #dddddd on surface #ffffff = 1.32:1 — technically below 3:1 for a UI boundary, but the card already carries adequate spatial separation via gap. 2px improves robustness).

Fix: border: 2px solid var(--color-border-card). New token --color-border-card introduced per palette (same hex as current --color-border to avoid regression).

Design Specification

Tokens — Tier Accent Colours (3 palettes × 3 tiers = 9 values)

All values are verified for WCAG 2.2 AA non-text contrast (criterion 1.4.11, minimum 3:1) against the card background token --color-surface: #ffffff, which is shared by all three palettes. The tier label text uses --color-muted (not the tier accent), so text contrast (1.4.3, 4.5:1) is evaluated separately under Typography.

Contrast ratios computed using the WCAG 2.1 relative luminance formula (L = 0.2126R + 0.7152G + 0.0722B with linearised sRGB channels).

Note on active state conflict: The existing .agent-card--active rule sets a 3px left accent in --color-accent. With the new tier rules, an active T1 agent would have both rules competing. The tier selector should have higher specificity (it is more informative). Frontend-engineer must order the tier selectors after the active rule so tier wins when both are present, or increase tier selector specificity to .agent-card--active[data-tier="1"] etc. Recommended resolution: bump the active-state rule to also use 4px to match tier weight; the active class merely ensures the accent is visible before JS populates data-tier (i.e., during the loading skeleton phase).

Decision: Include tier label. The operator's mockup explicitly shows "T1 Orchestrator", "T2 Curator", "T3 Leaf" as subtitle text. This text is essential to satisfy WCAG 1.4.1 (colour not sole differentiator for tier identity). Skipping it would leave colour as the only signal, which fails AA. The label is therefore mandatory, not optional.

Label text values per tier:

  • data-tier="1" → T1 Orchestrator
  • data-tier="2" → T2 Curator
  • data-tier="3" → T3 Leaf

Motion

No new animations. The existing transition: box-shadow 0.15s ease, border-color 0.15s ease on .agent-card will naturally animate the border-left colour change on hover. This is governed by the existing @media (prefers-reduced-motion: reduce) guard on the chevron. The border transition is not guarded — frontend-engineer should verify if the border-color transition on the card itself should also be disabled under reduced-motion (current code does not gate it; consider adding the transition to the guard as a SHOULD fix).

Breakpoints

No breakpoint changes. The tier accent stripe and label display identically at all widths. The existing 767px breakpoint for the single-column grid is unaffected.

References

RefSourceURLTakeaway applied
[R1] Refactoring UI refactoringui.com — "Use color to support, not define" and "Colored left border / side stripe as hierarchy signal" pattern The 4px left-stripe pattern is a canonical Refactoring UI technique for adding visual weight and categorical colour coding to cards without redesigning the card layout. The book explicitly warns against making colour the sole differentiator — hence the tier-label text requirement.
[R2] Material Design 3 m3.material.io/styles/color/roles M3's "container" vs. "on-container" colour role model informed the decision to use the tier accent only on the border stripe (a decorative container edge), not as background fill, avoiding low-contrast text-on-colour problems. The stripe is structural, not filled — no foreground text sits on it.
[R3] WCAG 2.2 w3.org/WAI/WCAG22/quickref/#use-of-color (Criterion 1.4.1) and 1.4.11 1.4.1 requires a non-colour redundant cue for information conveyed by colour — drives the mandatory tier-label text. 1.4.11 sets the 3:1 floor for UI component borders — drives the contrast floor for all 9 accent tokens.
