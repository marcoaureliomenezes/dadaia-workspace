Summary

Phase E BE strand implements the full CodexRuntimeAdapter.liveness method (PR5-E1) and performs the pricing.py audit confirming no Codex mis-firing (PR5-E2).

PR5-E1: Replaced the Phase A stub (always "idle") with a real implementation that reads ~/.codex/state_5.sqlite (read-only URI mode) for threads.updated_at and threads.archived, and tails ~/.codex/history.jsonl (last 200 lines via collections.deque) for the most recent ts matching the session. Performance

No performance budget was declared for this task. The liveness method is called only during aggregation (one call per session row), not in a hot loop. The collections.deque(fh, maxlen=200) tail reads at most 200 lines in O(N) with O(1) memory overhead relative to file size. SQLite is opened read-only with URI mode, which prevents write-lock contention on the live Codex process.

Data model

No schema changes. The implementation reads threads.id, threads.updated_at (Unix seconds INTEGER), and threads.archived (INTEGER 0/1) from ~/.codex/state_5.sqlite. These columns were confirmed by inspecting the live schema with .schema threads.

Schema note: updated_at_ms column exists (milliseconds) but updated_at (seconds) is used to match the history.jsonl ts format (also Unix seconds). No conversion needed.

API contract

No new endpoints. The RuntimeAdapter.liveness protocol signature is unchanged: liveness(session_id: str, cwd: str) -> Literal["active","idle","ended"]. All existing callers remain compatible.

Observability

The liveness method does not log on graceful degradation (intentional: avoids log spam on every aggregation cycle when Codex is not installed). The outer try/except Exception silently returns "idle". If Codex is installed and the DB is readable, errors would propagate to the inner _classify_liveness and be caught there.
