## Record

- `specs/bugs/BUGS.jsonl` holds one `bug-record-v1` object per id, and an id holds at most one plain record across the live ledger and the archive; a legacy `event` line of the archive is migration history, not a record. Registration facts are immutable; `solution`, `fix_sha`, `fix_files` and `superseded_by` are write-once; `surface` is an optional legacy property that only records filed before fix files were recorded carry; `status`, `closed_at`, `cause`, `caused_by` and `correlates` are governance fields; unknown fields are rejected.
- Status is `open | resolved | superseded | rejected`. Terminal records carry `closed_at`; a reopen is a new id.
- A record's fix is the newest commit, reached from HEAD of the main repo or else of a repo the context owning that main repo associates with it (as `context list --json` of the workspace holding the main checkout names them, never another context's checkout), whose message holds a line `fix(bugs): <id> — …` (a group lists its ids, separated by commas or blanks) or the REBUILD `refactor(bugs): <id> — …`; a commit HEAD reverts does not count (`Revert "<S>"` retires exactly one older commit subjected `<S>`, the nearest, and git's `Reapply "<S>"` reads as the revert of that revert), and a revert whose own message holds the id line is the fix. `_git.fix_commit` is that one finder over the repos it is handed, reading each in one `git log` and pulling the next only while an id is missing, so the context's registry is read only when the main repo itself misses an id.
- A resolved record persists `cause`, `solution`, `caused_by`, `fix_sha` (SHA-1 or SHA-256) and `fix_files`, both derived at resolve from that commit; `fix_sha` is a write-once hint a history rewrite may orphan, never judged. Git supplies the diff, numstat and subsequent history.
- `check` refuses each live resolved record carrying a `fix_sha` whose id line no commit reaches, one finding each, every one carrying the same fix: the one `bugs.py archive` of all the missed ids; a rebase, a `worktree sync` or a push-gate fold keeps the fix found, since each keeps the message. Only when a miss exists and one of those repos is a shallow clone are the misses one finding, with that repo's `git fetch --unshallow` as its fix.
- `caused_by` names a live or archived bug, a known task id or `none`; a task id is known when a job file or a closed release's `TASKS.md` carries it, in the current grammar or as the head of a historical task line (`T-<n>-<n>`, lettered `J<X>.S<n>.T<n>`); validation rejects dangling links and cycles.

## Writer and transitions

- `bugs.py` is the one writer and validator. Reads are `status`, `stats` (counts per field, then one `rebuild-due:<path>` line, with its ids, for each path two or more distinct fix commits of live or archived records touched, a record without `fix_files` read from its id commit, all such commits of a repo in one batched `diff-tree`; with `--closed-after <ts>` and/or `--closed-until <ts>` it adds `closed`, `fix-induced` (closed records whose `caused_by` is not `none`) and `rebuild-due` counts for the records closed in that window) and `check` (`check` prints each finding with its `fix:` line on the next line, and a ledger that is not UTF-8 is one finding carrying the `Agent action:` to re-encode the failing line as UTF-8 in place, every other line kept); writes are `append`, governance `update`, `resolve`, `supersede`, `reject` and `archive`.
- Registration follows an operator-confirmed proposal naming the violated contract and reproduction. `append` takes no surface: it refuses an id a live record or a plain archive record holds, with its `--bug-id` fix, and a `--component` text that names no tracked path (read through the kernel git runner), prints each earlier live or archived bug whose `fix_files` lie under a path the component names and, for such a path, the REBUILD due (`REBUILD due: <ordinal> bug on <path>`, the ordinal one past the count of distinct earlier fix commits), takes `--correlates` repeated or comma-separated, or `none`, and refuses ids that neither the ledger nor the archive holds, and subjects every supplied value to the publication privacy matcher.
- `resolve` requires cause, lineage and solution, takes no sha, and derives `fix_sha` and `fix_files` from the record's fix commit, refusing with one fix line — commit the fix with its id line, then resolve again — when HEAD reaches none. `supersede` names the replacement; `reject` records the reason. `update --set correlates=<a>,<b>` rewrites the correlate list under the same known-id refusal, so a correlate found after registration is recordable. The schema's mutability classes prevent generic update from changing transition-owned state.
- `archive` moves named terminal records into the bug history. Open records cannot be archived.
- One reader tells archive records from event lines: a plain line is a record, and a legacy event line contributes its `data` to lineage and history only. The one validation path, run by `check` and by every write on its candidate bytes, refuses a live id that is also a plain archive record and two plain archive records of one id, each with the `Agent action:` to revert the commit that wrote the line; one history reader, the live ledger plus that archive, serves `append`'s earlier-bug lookup and `stats`; the `verdict.py stats` readout reaches it only by running `bugs.py stats`.
- Every candidate ledger is validated before atomic replacement, so a refusal leaves both live and archived bytes unchanged.
- Every timestamp comes from the one clock; no verb takes a timestamp argument.
- `dd-bug-resolution/scripts` also holds the kernel the other skill scripts and the package load for every shared fact: the refusal with its one printer and the one `fix:` spelling and parser, `act(kind, text)`, the one producer of the `Agent action:` and `Operator action:` labels, the git runner with its scrubbed environment (repo-selecting `GIT_*` removed, bytecode writing off, so no child it starts writes `__pycache__`, and `DADAIA_WT=1` marking a sanctioned run), the one main-checkout helper `_git.main_checkout` (the parent of the git common dir, so a linked worktree and its main checkout answer alike; `.` outside a repository), the one fix-commit finder `_git.fix_commit`, the one context reader `_specs.context_row` (the `context list --json` row owning a repo, the CLI of the workspace holding its main checkout, found by position, run with the fence lifted for that one root; a failing CLI refuses with its own fix) and the repo set built on it `_specs.context_repos` (the repo alone when it is no repository or that workspace holds no registry or no CLI), the one relay of a child's refusal `_refusal.relay` (the exit status decides; ## Resolution discipline

- Read matching records and their named fixes before changing code. At most the twenty most recent fix-file/component matches and their fix commits belong to one fix investigation.
- Bugs sharing a cause are fixed together. Two failed fix attempts on one bug hand it to a fresh session with a written diagnosis.
- Establish the lowest-level RED behavior first, then fix the owning seam. The fix hardens the contract test in that contract's one home: it tightens an assert or adds the missing partition, never loosens or removes one, and the reviewer confirms the hardened test goes red with the fix reverted; the fix commit carries the bug's id line, which `resolve` reads.
- Two prior fixes on the touched module, or a `caused_by` other than `none`, require a REBUILD that keeps regression coverage.
- Any confirmed bug in code the work branch holds takes a hotfix lane, in any phase. After a candidate enters CLOSURE, in code only its `wt-rc` holds only a block-list bug lands, fixed by commits on that `wt-rc`, the only path whose `test(` and fix commits name `block: <item>`; any other bug there, REBUILD or demand is a job of the next candidate. Other confirmed bugs become explicit candidate scope; ship may carry an open id only through the exact operator authorization enforced by [[release-lifecycle]].
- The next candidate's bug-window review owns KEEP or REBUILD maturity. No runtime balance, source-quality reconstruction or cached candidate placement lives in the ledger.
