## The hierarchy

- A tree is `worktrees/<repo>/<name>` on branch `wt/<name>`; its name is its path, and its leaf fixes its kind: `<v>/rc-<N>/wt-rc` (the rc's integration branch), `<v>/rc-<N>/job-<n>/wt-main` (a job), `<v>/rc-<N>/job-<n>/wt-task-<kkk>` (a task, three digits), and the lanes `<v>/wt-backlog-<slug>` and `<v>/wt-hotfix-<bug-id>`; a slug or bug id is the backlog slug grammar. Any other name is refused with `not a worktree name`, its expected shapes spelled with the live version when the repo has one work branch, else `<M.m.p>`, and the `Agent action:` to rerun with a name of that shape; the leaf grammar has one reader, `NAME_RE`'s owner.
- One path reader serves the gate, the doctor, the reaper and every verb: the tree name runs to the first `wt-` segment under `worktrees/<repo>/`. The base derives from the name alone — a task's is its `wt-main`, a `wt-main`'s its `wt-rc`, a `wt-rc`'s and a lane's the work branch `<work><v>` — and no base is recorded anywhere else.
- `<v>` must be the version of the repo's one local work branch. One rule names it — `_worktree_git.work_versions` lists the `<work><M.m.p>` branches under one ref prefix (`for-each-ref`, local `refs/heads` by default) and `work_version` picks the one — and `core.gitflow.work_branch`, `specs init`, `context baseline`, `context dead`, the doctor's first-pass fix and the push gate read the same local rule; only `context alive` reads the `refs/remotes/origin` prefix, through `core.gitflow.origin_work_branch`, and takes the highest version with no act ([[context-management]]). Two local work branches refuse with one `Agent action:` that strands no commit, never deletes the checked-out branch and prints only what runs now, at most three steps a pass: switch to the higher, kept branch, then, when the higher holds the lower, unset the lower's upstream if it has one (git's `-d` judges an upstream, not HEAD) and `git branch -d` it, else merge the lower into the higher, so the next pass deletes it. One decision, `several_work`, yields the kept version and that act. `_worktree_git.drop_argv` is the one decider of whether a branch is merged into a target and how it goes: from one `for-each-ref --merged` read it yields unsetting the branch's upstream when it has one, then `git branch -d`, never `-D`, and nothing when the branch is unmerged. `drop_steps` spells that argv as act steps after checking the target out (git's `-d` judges the checkout) for the several-work act and the orphan row; `_remove` in `_worktree_end.py` runs it for every `merge` and `clean` and holds the one unmerged refusal. With no work branch, the refusal's fix creates `<work><M.m.p>` (the live release's version, else the next patch after the highest tag) from its remote branch when one exists, else from the integration branch.
- `new` cuts a tree from its parent's branch and refuses while that branch is absent, its fix the `new` of the parent. A `wt-main` opens only while the `_RELEASE.json` in its `wt-rc` tree, the context's main repo's even for an associated repo's job, passes `release.py check` and reads `IMPLEMENTATION`: a state check refuses is refused with check's first finding and fix line, an absent state reads as not `IMPLEMENTATION`; the wrong-phase refusal's fix is chosen by the phase read, since a phase never goes back: at `CLOSURE` the `new` of the next candidate's `<v>/rc-<N+1>/wt-rc`, else the `Agent action:` to reach `IMPLEMENTATION` in that `wt-rc` tree; an absent `wt-rc` tree whose branch lives refuses with the one re-attach line, `git worktree add` locked as `new` locks it; a hotfix lane only while the main repo's `BUGS.jsonl` on the work branch holds that bug open, refused otherwise with the `Operator action:` to confirm that bug, or for a bug the ledger already holds, the regression as a new bug; a lane path in any state but `absent` is refused with the act that state names (Verbs and lifecycle).
- `new` writes a short `AGENTS.md` once into each level folder it creates (`<v>/`, `rc-<N>/`, `job-<n>/`), never over an existing file. One owner decides the level-folder rule for `new`, `merge` and `list`: a level folder sits at its depth under `worktrees/<repo>/` and is named for it; `list` reports no stray for one holding only its file, and a folder named for no level is a stray at any depth.
- `wt-rc`, `wt-main` and backlog branches are pushable; task and hotfix branches stay local.

## Merges and gates

- Every kind's checks start with a clean tree and end with the ignored-file check and the parent checkout being on the parent branch; `merge` fast-forwards the parent's checkout — the `wt-rc` tree for a `wt-main`, the `wt-main` tree for a task, the repo for a `wt-rc` or lane.
- A task lands on `wt-main` unreviewed, with ancestry, RED/implementation separation and the denylist scan: a non-`test(` commit touching a declared test glob, or with none declared the one built-in rule (a path under a `tests` folder at any depth or named like a test, never inside a tooling dot-folder such as `.github/`), is refused, and a `test(` commit touching any other path is refused too, its act moving that path to the implementation task; each commit's paths are read NUL-separated, so a path with blanks is one path; RED tests and implementation arrive through fresh, separate task dispatches. A parent tree removed by hand is refused with the same locked re-attach line.
- A task, hotfix or backlog merge refuses a tree whose `<base>..HEAD` objects carry a denylisted term or a baseline secret: `dadaia ci push-gate-check --onto <base>`, the pre-push content matcher with no branch policy, run on the tree with the denylist file the ledger's one choice (`_ledger.denylist_file`) names handed to it through the loader's own `DADAIA_PRIVACY_DENYLIST` input, none when no file holds a term; its refusal names the merge, and its fix is the gate's `Agent action:` naming the listed paths: remove the term from them in the unpublished commits, reworded or split by hand, so a fresh verdict must name the new HEAD ([[sdd-gate-v3]]). A `wt-main` or `wt-rc` merge runs no scan.
- A `wt-main` lands on `wt-rc` and a hotfix lane on the work branch through the job gate: ancestry, one reviewer-authored `APPROVED` verdict naming HEAD, or a sha HEAD or the branch reflog reaches outside the base, whose `diff_sha256` is HEAD's — the hash of the plumbing diff over the merge-base and of the commits' (patch-id, message) series, author and dates unbound — so a dropped or reworded commit needs a fresh verdict and the merge lands the HEAD it judged (no verdict is rebound); the refusal ends in one act that clears it: an invalid verdict file its `reports validate <file> --reviewed-root <tree>`, a `REJECTED` one the `Agent action:` to fix its findings and dispatch the reviewer on the new HEAD, and no verdict or one bound to another diff the dispatch of the reviewer on HEAD; and the base's tracked `verify:` run once as argv with the workspace venv first on `PATH` and bytecode writing off (the kernel child env sets `PYTHONDONTWRITEBYTECODE`), so the gate leaves no `__pycache__` in the tree; the merge is the one run of `verify:`, no preflight runs before review, and a repo declaring no `verify:`, or one that is not a startable argv list, refuses with one act: land that `AGENTS.md` line through a `wt-backlog` lane, then `sync` the tree that owns the refused merge's base. A red `verify:` names where its fix lands by the judged tree's kind: a `wt-main` in a task of its job; a `wt-rc` in the `wt-rc` when a reconcile commit is at fault or only the release's own job code fails (that bug registered first), else through a `wt-hotfix` lane when the work branch's `verify:` fails too, then its `sync`; any other tree in itself. Both refuse while git tracks any path under `tests/tmp/job-<n>/` (a hotfix: `tests/tmp/<bug-id>/`; only the index counts) with an `Agent action:` to promote each scaffold test into its contract's home (a delete needs the operator's order).
- A `wt-rc` lands on the work branch through the same job gate, then, in the main repo, `bugs.py`, `backlog.py` and `release.py` `check` and the workspace doctor on its `specs/`, a red one relaying its own first `fix:` line. Every merge runs the instance's projected ledger scripts, never a script the tree tracks; an associated repo holds no `specs/`, so its merges run no ledger check. A backlog lane lands `specs/` and the repo's `AGENTS.md` only: reviewed, then those ledger checks, never a test or `verify:` run.
- A `wt-main` or `wt-rc` lands only with no tree below its folder open, the fix naming the open tree's `merge`.
- The `verify:` line splits on whitespace alone: a quote groups a word and a backslash stays literal, so a Windows path reaches the command intact.
- A base that moved past a tree is refused with that tree's `sync` through `dadaia worktree` as the fix.

## Verbs and lifecycle

- `new`, `merge`, `clean`, `sync`, `hash`, `list`, `pause` and `resume` are the complete verbs. `dadaia worktree <verb> …` runs the installed `worktree.py`, forwarding argv, output and exit code; with no installed script it refuses with `public install` as the fix. Every git child the verbs start carries `DADAIA_WT=1`, the sanctioned-run marker.
- One decider, `_worktree_git.state`, reads a lane path for every verb and for `list`, each state with the one act that ends it: `normal` (git lists the branch's tree there), `held` (the branch's tree sits at another path: move it back), `foreign` (another worktree sits there: land its work, then switch it onto the branch, or remove it when the branch is gone; one detached at or behind its own branch just switches onto it), `folder` (files git does not list: stop what holds them open, then move the folder aside, since it may hold work), `branch` (the branch with no tree: its `merge`), `paused` (a bundle holds it: its `resume`) or `absent` (its `new`). `merge`, `clean` and `pause` take `normal` or `branch`, `hash` and `sync` `normal`, `resume` `paused` and `new` `absent`; any other state refuses with its act, touching nothing.
- `merge` lands the exact reviewed head, removes the worktree, deletes its local branch, removes a pushed upstream branch when applicable and drops each level folder left holding only its `AGENTS.md`, or left empty. Ignored files the tree holds refuse it with one act offering `--keep <files>` or `--drop`. It never rebases or force-deletes. A path with no tree and no branch is never success: it refuses with that path's `new` as the fix. It re-runs cleanly after a stop: with the tree gone and the branch left, once the parent checkout is on its base (else the `git switch` to it is the fix), a merged branch is removed as a live tree is (the absent tree pruned) and an unmerged one refuses with the locked re-attach line, a folder at the path moved aside first. A removal git fails on that leaves files at the path refuses with the `folder` act, never a delete. A git failure no check names ends as one refusal naming the git act that failed, whose fix clears it and reruns the same call, its tree path spelled absolute, never a traceback.
- `clean` drops one of our trees holding no commit ahead of its base, and on a branch with no tree runs `merge`'s no-tree ending; a tree with commits is refused with the `Agent action:` to dispatch the reviewer on its HEAD, then run its `merge`.
- `pause <path>` sets a clean lane or `wt-rc` tree aside: it writes `git bundle create <file> <branch> --not --remotes=origin` (the commits no `origin` ref holds) to `.dadaia/dist/<repo>/<name>.bundle`, verifies it, removes the tree (a branch with no tree is bundled as the repo has it) and its level folders left empty, and deletes the local branch by `update-ref -d` under the CLI marker; nothing is committed or pushed. It refuses first, touching nothing: a job or task tree, a lane path in a state but `normal` or `branch`, a dirty tree (commit first), a tree holding ignored files other than caches and `*.pyc` (delete or commit them; caches drop with the tree), a `wt-rc` with a tree open below it, a branch origin already holds whole (its `merge`), an existing bundle holding a commit the branch lacks (the act moves that bundle aside), and a bundle write or verify that fails, which leaves no file.
- `resume <path>` recreates the `wt/*` branch at the bundled tip and the locked tree with its level files, then deletes the bundle and the `dist/<repo>/` folders it leaves empty; it takes only a `paused` path: any other state refuses with its act, and a path with no branch and no bundle with the `Agent action:` to rerun with the tree of a bundle under `.dadaia/dist/<repo>/`. A pushed lane or `wt-rc` resumes too, since the bundle carries only what origin lacks.
- `sync <path>` rebases the `normal` tree at *path* and every open tree below it, parents first, each `--onto` its base from the commit it was cut from (its merge-base, read for every tree before any parent moves and saved as the branch's `syncfork`, which a re-run reuses while the tree still holds it), so a commit once on the parent and later removed from it is never dropped; a tree already holding its base is skipped, a dirty tree stops the run before any tree moves, and a conflict aborts that rebase and stops with one fix line naming the same `--onto` rebase; a re-run finishes. It never pushes.
- `list --json` derives state from git and `.dadaia/dist/`, one row per path, each carrying its leaf's `kind` (none for a row off the grammar) and a line: `ready`, `open`, `empty` (nothing ahead of its parent branch), `paused` (one row per pause bundle, kind `paused`, its exit the `resume` line), `orphan` (a `wt/*` branch with no tree, or a listed tree whose folder is gone: on the grammar its line is its state's act, the `merge`, or the `folder` act when files sit at its path; off the grammar, the `drop_steps` act against the one live work branch when that branch holds it, else no exit and an `Agent action:` to land or archive it), `foreign` (a linked worktree of the repo that is no tree of this workspace, its fix an `Agent action:` to land its work, then `git worktree remove --force --force` it, or at a lane path its state's act) or `unregistered` (a stray folder at any depth under `worktrees/<repo>/`, its fix the act to move it aside, never a delete). A linked tree of a repo no context owns is `unregistered` with `registered: false`, its fix an `Agent action:` to land its work and remove it. No worktree state file exists.
- Release closure waits while the repo has any row but a `wt-rc` and the tree it runs from, paused trees, trees and orphan branches of the old grammar included, and prints that row's `exit`, else its `fix`; context death waits on every row but a paused one, and context deletion waits on a paused one ([[release-lifecycle]], [[context-management]]). Tool environments and caches live at workspace level, never inside a worktree.
- Only the main thread opens and merges; leaf agents work only in the path they receive.
