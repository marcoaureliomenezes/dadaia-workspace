## The command

- `dadaia doctor` is the one validator; `dadaia specs doctor` and `dadaia backlog doctor` do not exist (deleted, not aliased); `dadaia public doctor` (library vs projection) and `dadaia reports doctor` (handoffs) are the only other doctors, each diagnosing its own tree and deleting no instance file.
- Three Compliance sections run in fixed order — `workspace` (root, harness dirs, `.dadaia/` zones), `specs` (the SPEC-DOC/TREE/memory/RELEASE-TREE rules over one `specs/` tree), `ledgers` (BL-* over `BACKLOG.json` plus schema validation of every committed governance record).
- One rule record, `core/doctor_rules.py::Rule(codes, section, run, fix, fix_help)`: `features/spec_context/doctor.py::workspace_rules`, `features/specs/rules.py::RULES`, `features/backlog/doctor.py::RULES` and `features/specs/ledgers.py::RULES` each contribute a tuple over their own context and issue type; `cli/commands/doctor.py` is the only place the sections meet, one render adapter per section, no cross-feature import.
- Every printed finding is one line `<CODE> <verdict> <message>`, the verdict being the section's own word — `canon|operator|slop|expired|missing` for the walk, `error|warning|info` for `specs` and `ledgers` — with no mapping between the vocabularies.
- Each section ends with `compliance(<section>): N/M <unit> canonical (P%)` — units are entries, rules and records respectively — and the run ends with `compliance(total): N/M checks canonical (P%)`; `P` is the integer floor of `100·N/M`, one formula for every line and for `--json`.
- Exit 1 on any error-class finding in any section: a `slop`, `expired` or `missing` entry, a context invariant, an ERROR-severity specs rule, any ledger finding.
- `--json` mirrors the run as `{"specs_dir", "sections": {<name>: {"findings": [{code, verdict, message}], "compliance": {canonical, total, percent}}}, "compliance", "fixed"}`; `--quiet` prints only what `--fix` deleted; `--redact` masks every foreign context name and repo slug at the render boundary ([[context-management]]).
- The tree the `specs` and `ledgers` sections read resolves from `--context <name>` (`repos/<name>/specs`), `--specs-dir <path>` (mutually exclusive), else the bound context; with no resolvable tree those two sections are empty and the `workspace` section still runs — the SessionStart reaper runs exactly there; `--public-dir` enables template and scaffold drift checks; `--source-root`/`--alias-map` feed the backlog anchor derivation.
- The CI hygiene job runs `dadaia doctor --specs-dir specs --source-root .` over the checked-out tree ([[QUALITY]]).

## The `workspace` section

- The walk covers, in one fixed order, the root, the harness dirs (`agents` plus the profile's `claude codex kimi-code`), the `.dadaia/` top level, the closed-canon zones `states dist sessions` and the TTL zones `handoff tmp mcps .cache`; `references/` and `.venv/` are never walked and a symlink is never followed.
- Every entry gets one verdict: `canon`, `operator` (matches an instance exception), `slop`, `expired` (older than the zone's one-day TTL by mtime, or a directory emptied by expiry) or `missing` (an init/install zone or `states/harness_profile.json` absent); `canon` + `operator` are the numerator, every entry classified is the denominator.
- Canon per level: root — the root law's directories and files (`.env` and `.gitignore` included); harness dirs — an entry the install ledger names, a directory holding one being descended, not judged; `.dadaia/` — the zone names plus `AGENTS.md` and `.gitignore`; `states/` — the `STATES_CANON` files, `presence/` and `AGENTS.md`; `dist/` — `spec-contexts.json`; `sessions/` — `*.json`; a TTL zone's own `AGENTS.md` — canon by projection, never a TTL candidate; every set is a view of `core/workspace_layout.py`'s zone registry, spelled nowhere else ([[ARCHITECTURE]]).
- Instance exceptions are `.dadaia/states/instance_exceptions.txt`: one glob per line, `#` comments, deduplicated, order kept, matched against the entry name and its root-relative path at the root and inside the harness dirs; the root-whitelist hook reads the same file ([[sdd-gate-v3]]).
- The finding code is `WS-<zone>-<verdict>`, `<zone>` being `root`, the harness dir, `dadaia`, or the zone name without its leading dot; the message is the entry path and its detail.
- The context invariants ride the same section outside the scored entry set, always error-class: `INV-4`/`INV-5`/`CTX-URL-1` (ALIVE/DEAD repo and URL coherence), `INV-6` (a repo slug owned by two contexts, report-only), `PRESENCE-GC` (stale advisory presence), `VENV-1` (venv entrypoint health, never auto-fixed).
- `--expired-only` scopes the section to the TTL lane: invariants skipped, only expired entries scanned and scored.

## The `specs` section

- The unit is the rule: a rule that emitted no error or warning is canonical, whatever the size of the tree it walked; `features/specs/rules.py::RULES` is the one ordered registry from which check order, fix dispatch (`FIX_BY_CODE`) and the `--fix` help text all derive.
- Each run builds one fresh `SpecsTree` snapshot (`features/specs/specs_tree.py`) so the live release is parsed once; `features/specs/canon.py`'s `CANON` table is the one definition of what a `specs/` tree may hold — `scaffold` renders it, the doctor checks it, and a scaffolded tree passes by construction.
- `TREE-*` covers the canonical tree, required rule files and the absence of repo-local runtime state (`REPO-DADAIA-1`): `TREE-8` is the canon-root membership check, and `TREE-5` compares every scaffolded law file — root `specs/AGENTS.md` and every scoped one, `memory/AGENTS.md` included — against its source and `shipped-hashes.json`: a byte match with a shipped version is refreshed losslessly by `--fix`; a file matching neither its source nor any shipped version is `copy-drift`, reported and never overwritten.
- Release rules: `SPEC-DOC-003/009` (live release state and phase), `SPEC-DOC-004` (trio present and `**Status:** Aprovado`), `SPEC-DOC-005` (PLAN line limit), `SPEC-DOC-024` (phase vs task-marker coherence), `SPEC-DOC-026/027` (unique ids, one naming rule), `SPEC-DOC-039` (partial archived release dirs), `SPEC-DOC-044` (a verdict naming no live sha — head, first parent, develop tip — deleted by `--fix`), `SPEC-DOC-045` (`pyproject.toml` version equals the release id from CLOSURE on), `SPEC-DOC-046` (legacy `RELEASE.json` renamed by `--fix`), `SPEC-DOC-047` (a TASKS row whose write set names `specs/memory` — memory is closure procedure, never a task).
- `RELEASE-TREE-*` is `features/specs/release_tree.py::validate_release_tree` rendered as ERRORs — every `_RELEASE.json`, live and under `_archive/<id>/`, `_ideas/` excluded: `STATE-MISSING`, `SCHEMA` (`release-state-v1`), `PARSE`, `TS-ORDER` (`log[].ts` non-decreasing), `PHASE` (one of the four), `ARCHIVED` (iff under `_archive/`), `TRIO` (SPEC/PLAN/TASKS at root in IMPLEMENTATION or CLOSURE only); `rc-archive` and `release archive` refuse on the same validator ([[sdd-bug-backlog-governance]]).
- Memory rules: `SPEC-DOC-002/002L/008/010` (atoms present, Markdown, no history heading), `MEM-PLACEHOLDER-1` (unfilled scaffold atom, deleted by `--fix`) and `AGENTS-PLACEHOLDER-1` (an installed `tests/AGENTS.md` still carrying `<TOKEN>`), `CAT-1` (catalog slugs equal atom files), `LINT-1` (frontmatter against `memory-frontmatter-v1`, forbidden headings, duplicate headings, unresolved wikilinks — in-process, no script), `MEM-DRIFT-1` (`ARCHITECTURE.md`'s features package map vs the live `dadaia_workspace/features` tree, one WARNING per stale or missing package, silent when the heading or block is absent), `FIXED-1/2` (a fixed law section missing or differing from its library fragment, inserted or refreshed by `--fix`).
- Governance and audit rules: `SPEC-DOC-033` (every `BUGS.jsonl` line the bug store cannot parse), `SPEC-DOC-041` (a terminal bug record whose `closed_at` is past the archive threshold), `SPEC-DOC-035` (any item file loose under `specs/backlog/` other than `BACKLOG.json` and `AGENTS.md`), `SPEC-DOC-030` (audit dir shape `<YYYYMMDD>-<slug>`), `SPEC-DOC-036/038` (an `open` finding in an archived audit; a live audit whose findings are all terminal), `SPEC-DOC-034` (a missing `_archive/` dir, created by `--fix`), `SPEC-DOC-007` (orphan specs).
- Coherence rules: `SPEC-DOC-001/028/037` (constitution invariants, resolvable file references, no runtime enum) and `SPECS-VERSION` (`specs_pattern_version` 6; `dadaia specs upgrade` refuses a pre-v6 tree).

## The `ledgers` section

- The unit is the record, located `path:line`; two features contribute and never import each other — `features/backlog/doctor.py` over the parsed `BACKLOG.json` model and `features/specs/ledgers.py` over every committed governance file — and the two reports add into one score line.
- `BL-SCHEMA` (parse errors, status token, bound and resolvable `intents[]` beyond `idea`), `BL-CONFLICT` (two active items sharing an anchor incompatibly), `BL-STALE` (a live `active[]` slug that already has a `backlog_histo.jsonl` record, or whose own status is a terminal disposition).
- `LEDGER-<NAME>-SCHEMA` for `ADR` (`decisions.jsonl`, `decision-record-v1`), `BACKLOG` (`backlog-v1`), `BUGS` (`bug-record-v1`), `FINDINGS` (every `audits/*/FINDINGS.jsonl`, `finding-record-v1`), `BACKLOG-HISTO`, `AUDITS-HISTO`, `RELEASES-HISTO` (`histo-record-v1`, each with its own disposition subset from `core/models/histo.py`); `_RELEASE.json` is validated once, by the `specs` section, never here.
- Every schema is loaded by `features/specs/schemas.py` from the packaged `public/schemas/` tree; an absent ledger file is an empty record set, never a finding.
- The section has no fix: a committed record is repaired by hand or by the verb that owns it.

## The reaper

- `--fix` runs in order: `presence.gc` -> stale session records -> migrate `states/root_exceptions.txt` into `instance_exceptions.txt` -> seed missing (a zone directory; the harness profile from the L1 harnesses whose projection dir exists, through the profile store's one writer) -> delete expired -> delete slop -> remove a DEAD context's leftover repo -> the `specs` rules' own fixes (`MEM-PLACEHOLDER-1`, `REPO-DADAIA-1`, `TREE-4`, `TREE-5`, `TREE-8`, `FIXED-1/2`, `SPEC-DOC-034`, `SPEC-DOC-044`, `SPEC-DOC-046`).
- `--fix --expired-only` stops after "delete expired" and runs no specs fix; it is the SessionStart lane — every projected harness runtime config runs `<venv>/dadaia doctor --fix --expired-only --quiet` at startup and resume, a CLI process rather than a hook module.
- Structural slop dies only by an explicit `dadaia doctor --fix`; nothing is quarantined or moved, and a deletion target is removed only when its own location resolves inside the workspace, a symlink unlinked and never followed; every step reports what it did or that it skipped, never aborting the pass.
- A fix invents no approval, task completion, evidence, disposition or operator decision; it regenerates deterministic state only.
- Never touched: `references/` and `.venv/`, entries the install ledger names and the contents of `agentic/` and `hooks/` (hash drift belongs to `public doctor`, [[public-asset-distribution]]), a zone's `AGENTS.md`, entries matching an instance exception, unexpired files, a live session's own presence record, any ledger record.
