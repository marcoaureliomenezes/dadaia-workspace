## The command

- `dadaia doctor` is the one validator — the former per-area specs and backlog doctors were deleted, not aliased; `dadaia public doctor` (library vs projection) is the only other doctor, diagnosing its own tree and touching no instance file.
- Three sections run in fixed order — `workspace` (root, harness dirs, `.dadaia/` zones, the ALIVE repo trees, the installed git hooks), `specs` (the SPEC-DOC/TREE/memory/RELEASE-TREE rules over one `specs/` tree), `ledgers` (BL-* over `BACKLOG.json` plus schema validation of every committed governance record).
- One rule record, `core/doctor_rules.py::Rule(codes, section, run, fix, fix_help)`: `features/spec_context/doctor.py::workspace_rules`, `features/specs/rules.py::RULES`, `features/backlog/doctor.py::RULES` and `features/specs/ledgers.py::RULES` each contribute a tuple over their own context and issue type; `cli/commands/doctor.py` is the only place the sections meet, one render adapter per section, no cross-feature import; there is no score — a run is its findings and its exit code (ADR 0016).
- Every printed finding is one line `<CODE> <verdict> <message>`, the finding verdict being the section's own word — `canon|operator|reaped|slop|expired|missing` for the walk, `error|warning|info` for `specs` and `ledgers` — with no mapping between the vocabularies.
- Every error-class rule carries a mandatory `fix_help`, rendered as one `fix: <command>` line under each of its findings — `dadaia doctor --fix`, `--fix --expired-only`, `ci install-hook --force`, or the governance verb owning the record — so the exit-1 run never stalls the flow ([[sdd-gate-v3]]).
- Exit 1 on any error-class finding in any section: a `slop`, `expired` or `missing` entry, a context invariant, `HOOKS-DRIFT-1`, an ERROR-severity specs rule, any ledger finding.
- `--json` mirrors the run as `{"specs_dir", "sections": {<name>: {"findings": [{code, verdict, message, fix}]}}, "fixed"}`; `--quiet` prints only what `--fix` did; `--redact` masks every foreign context name and repo slug at the render boundary ([[context-management]]).
- The tree the `specs` and `ledgers` sections read resolves from `--context <name>` (`repos/<name>/specs`), `--specs-dir <path>` (mutually exclusive), else the bound context; with no resolvable tree those two sections are empty and the `workspace` section still runs — the SessionStart reaper runs exactly there; with no instance around the run (CI over a bare checkout) the `workspace` section is empty and an explicit tree still gets its two sections, and only a run with nothing to read refuses with the `dadaia init` message; `--public-dir` enables template and scaffold drift checks; `--source-root`/`--alias-map` feed the backlog anchor derivation.
- The CI hygiene job runs `dadaia doctor --specs-dir specs --source-root .` over the checked-out tree ([[QUALITY]]).

## The `workspace` section

- The walk covers, in one fixed order, the root, the harness dirs (`agents` plus the profile's `claude codex kimi-code`), the `.dadaia/` top level, the top of every ALIVE registered repo (main plus associated), the closed-canon zones `states dist sessions` and the TTL zones `handoff tmp reaped mcps .cache`; `references/` and `.venv/` are never walked and a symlink is never followed.
- Every filesystem act of the walk and the reaper — `walk`, `mtime`, `move`, `remove` — is `features/spec_context/sweep.py`, one primitive behind one guard: a symlinked root is empty, an entry that vanished mid-walk is absent, a location outside the workspace is skipped (source and destination alike), every `OSError` is one `skipped` action and a cross-device move is copy-then-remove inside the primitive; `scan()` and `fix()` share that one walk.
- Every entry gets one finding verdict: `canon`, `operator` (matches an instance exception), `slop`, `expired` (older than the zone's TTL by mtime, or a directory emptied by expiry), `missing` (an init/install zone or `states/harness_profile.json` absent) or `reaped` (held in `reaped/`, listed `(Nd left)`, canonical, never scored); `canon` + `operator` are the numerator, every scored entry the denominator.
- Canon per level: root — the root law's directories and files (`.env` and `.gitignore` included); harness dirs — an entry the install ledger names, a directory holding one being descended, not judged; `.dadaia/` — the zone names plus `AGENTS.md` and `.gitignore`; `states/` — the `STATES_CANON` files, `presence/` and `AGENTS.md`; `dist/` — `spec-contexts.json`; `sessions/` — `*.json`; a TTL zone's own `AGENTS.md` — canon by projection, never a TTL candidate; every set is a view of `core/workspace_layout.py`, spelled nowhere else ([[ARCHITECTURE]]).
- A repo tree: canonical at the top is anything not on `REPO_TREE_EXCLUDED` (`.dadaia` plus `.venv .pytest_cache .mypy_cache .hypothesis .ruff_cache test-results playwright-report coverage .coverage`); only an excluded name — at the top or at any depth — is a finding (`WS-repos-slop`), and the prune set `.git .venv node_modules` ends the descent before classification, so an untracked source entry is never judged and a nested virtualenv is never moved.
- Instance exceptions are `.dadaia/states/instance_exceptions.txt`: one glob per line, `#` comments, deduplicated, order kept, matched against the entry name and its root-relative path at the root and inside the harness dirs; the root-whitelist hook reads the same file ([[sdd-gate-v3]]).
- The finding code is `WS-<zone>-<verdict>`, `<zone>` being `root`, the harness dir, `dadaia`, `repos`, or the zone name without its leading dot; the message is the entry path and its detail.
- The context invariants ride the same section outside the scored entry set, always error-class: `INV-4`/`INV-5`/`CTX-URL-1` (ALIVE/DEAD repo and URL coherence), `INV-6` (a repo slug owned by two contexts, report-only), `PRESENCE-GC` (stale advisory presence), `VENV-1` (venv entrypoint health, never auto-fixed).
- `HOOKS-DRIFT-1`, its own rule: an ALIVE repo's installed `.git/hooks/{pre-commit,pre-push}` byte-differing from the shipped `public/scripts/` copy (`core/workspace_layout.INSTALLED_GIT_HOOKS`), `fix: .dadaia/.venv/bin/dadaia ci install-hook --force`; a checkout with no `.git/hooks/` directory (a linked worktree) is never a finding.
- `--expired-only` scopes the section's report to expired entries — invariants and hook drift skipped — and keeps the specs repairs off `--fix`; it never narrows what the reaper does.

## The `specs` section

- The unit is the rule: a rule that emitted no error or warning is canonical, whatever the size of the tree it walked; `features/specs/rules.py::RULES` is the one ordered registry from which check order, fix dispatch (`FIX_BY_CODE`) and the `--fix` help text all derive.
- Each run builds one fresh `SpecsTree` snapshot (`features/specs/specs_tree.py`) so the live release is parsed once; the canon rows are `core/workspace_layout.SPECS_CANON` — `features/specs/canon.py` renders them (`scaffold`) and checks them, and a scaffolded tree passes by construction.
- `TREE-*` covers the canonical tree and the required rule files: `TREE-8` is the canon-root membership check, and `TREE-5` compares every scaffolded law file — root `specs/AGENTS.md` and every scoped one, `memory/AGENTS.md` included — against its source and `shipped-hashes.json`: a byte match with a shipped version is refreshed losslessly by `--fix`; a file matching neither its source nor any shipped version is `copy-drift`, reported and never overwritten; a repo-local `.dadaia/` is the `workspace` walk's finding, not a specs rule.
- Release rules: `SPEC-DOC-003/009` (live release state and phase), `SPEC-DOC-004` (trio present and `**Status:** Aprovado`), `SPEC-DOC-005` (PLAN line limit), `SPEC-DOC-024` (phase vs task-marker coherence), `SPEC-DOC-026/027` (unique ids, one naming rule), `SPEC-DOC-046` (legacy `RELEASE.json` renamed by `--fix`), `SPEC-DOC-047` (a TASKS row whose write set names `specs/memory` — memory is closure procedure, never a task).
- `RELEASE-TREE-*` is `features/specs/release_tree.py::validate_release_tree` rendered as ERRORs — the live `_RELEASE.json` (documents under `_archive/<id>/` are parsed, never ranked): `STATE-MISSING`, `SCHEMA` (`release-state-v1`), `PARSE`, `TS-ORDER` (`log[].ts` non-decreasing), `PHASE` (one of the four), `ARCHIVED` (iff under `_archive/`), `TRIO` (SPEC/PLAN/TASKS at root in IMPLEMENTATION or CLOSURE only); the release verbs refuse on the same validator ([[sdd-bug-backlog-governance]]).
- Memory rules: `SPEC-DOC-002/002L/008/010` (atoms present, Markdown, no history heading), `MEM-PLACEHOLDER-1` (unfilled scaffold atom, deleted by `--fix`) and `AGENTS-PLACEHOLDER-1` (an installed `tests/AGENTS.md` still carrying `<TOKEN>`), `CAT-1` (catalog slugs equal atom files), `LINT-1` (frontmatter against `memory-frontmatter-v1`, forbidden headings, duplicate headings, unresolved wikilinks — in-process, no script), `MEM-DRIFT-1` (`ARCHITECTURE.md`'s features package map vs the live `dadaia_workspace/features` tree, one WARNING per stale or missing package, silent when the heading or block is absent), `MEM-DRIFT-2` (WARNING, unit = atom, no fix: a memory atom citing a `dadaia <verb>` absent from the live command tree or a `specs/`, `dadaia_workspace/` or `.github/` path absent from the repo — `features/specs/citations.py::dead_citations` over `cli/help_digest.py::command_paths()`, which the CLI root passes in as plain data; memory drift is closure work, never a red build), `ADR-SUPERSEDED-CITATION` (ERROR: a memory atom, skill, rule or scaffold citing an ADR id whose record is `superseded` — `features/specs/doctor_adr.py`), `FIXED-1/2` (a fixed law section missing or differing from its library fragment, inserted or refreshed by `--fix`).
- The `ledgers` section delegates: each skill script's `check --specs <dir> --json` runs as a subprocess and its lines re-emit as `LEDGER-<NAME>-SCHEMA` with a `fix:` naming the script; the doctor keeps no ledger schema of its own (0.4.7 c7).
- Governance and audit rules: `SPEC-DOC-033` (every `BUGS.jsonl` line the bug store cannot parse), `SPEC-DOC-041` (a terminal bug record whose `closed_at` is past the archive threshold), `SPEC-DOC-035` (any item file loose under `specs/backlog/` other than `BACKLOG.json` and `AGENTS.md`), `SPEC-DOC-030` (audit dir shape `<YYYYMMDD>-<slug>`), `SPEC-DOC-036/038` (an `open` finding in an archived audit; a live audit whose findings are all terminal — `fix:` names `audit.py disposition`/`audit close`), `SPEC-DOC-034` (a missing `_archive/` dir, created by `--fix`), `SPEC-DOC-007` (orphan specs).
- Coherence rules: `SPEC-DOC-001/028/037` (constitution invariants, resolvable file references, no runtime enum) and `SPECS-VERSION` (`specs_pattern_version` 6; `dadaia specs upgrade` refuses a pre-v6 tree).

## The `ledgers` section

- The unit is the record, located `path:line`; two features contribute and never import each other — `features/backlog/doctor.py` over the parsed `BACKLOG.json` model and `features/specs/ledgers.py` over every committed governance file — and the two reports add into one score line.
- `BL-SCHEMA` (parse errors, status token, bound and resolvable `intents[]` beyond `idea`), `BL-CONFLICT` (two active items sharing an anchor incompatibly), `BL-STALE` (a live `active[]` slug that already has a `backlog_histo.jsonl` record, or whose own status is a terminal disposition).
- `LEDGER-<NAME>-SCHEMA` for `ADR` (`decisions.jsonl`, `decision-record-v1`), `BACKLOG` (`backlog-v1`), `BUGS` (`bug-record-v1`, plus the model's own invariants — a terminal record without `closed_at`, a retired provenance key), `FINDINGS` (every `audits/*/FINDINGS.jsonl`, `finding-record-v1`), `BACKLOG-HISTO`, `AUDITS-HISTO`, `RELEASES-HISTO` (`histo-record-v1`, each with its own disposition subset from `core/models/histo.py`); `_RELEASE.json` is validated once, by the `specs` section, never here.
- Every schema is loaded by `features/specs/schemas.py` from the packaged `public/schemas/` tree; an absent record file is an empty record set, never a finding.
- The section's one fix is `LEDGER-BUGS-SCHEMA`'s: `--fix` re-serializes a record that parses but fails the schema or the model's invariant — stripping a retired key, back-filling a terminal record's missing `closed_at` — losslessly, in `BUGS.jsonl` and `bugs_histo.jsonl`; every other ledger finding is repaired by the verb that owns the record.

## The reaper

- `--fix` runs one lane, `DoctorService.fix()`, in order: marker GC -> stale session records -> migrate `states/root_exceptions.txt` into `instance_exceptions.txt` -> seed missing (a zone directory; the harness profile from the L1 harnesses whose projection dir exists, through the profile store's one writer) -> move every `slop` entry -> move a DEAD context's leftover repo (`INV-5`, refused unless it resolves to a direct child of `repos/`) -> delete expired; then, unless `--expired-only`, the `specs` rules' own fixes (`MEM-PLACEHOLDER-1`, `TREE-4`, `TREE-5`, `TREE-8`, `FIXED-1/2`, `SPEC-DOC-034`, `SPEC-DOC-046`) and the `ledgers` re-serialization of `LEDGER-BUGS-SCHEMA`.
- Nothing is deleted directly: slop and INV-5 leftovers are MOVED to `.dadaia/reaped/<YYYYMMDD>/<workspace-relative-path>` — the `reaped` zone, EPHEMERAL, 7-day TTL clocked at the move, one hold per origin per day (a re-reaped origin replaces its earlier hold and restarts the clock) — and deletion happens only when a TTL zone's entry expires, `reaped/` included; the origin path is the whole record of where an entry came from.
- The same lane runs at SessionStart (every projected harness runtime config runs `<venv>/dadaia doctor --fix --expired-only --quiet` at startup and resume, a CLI process rather than a hook module) and on the PostToolUse hook's throttle through `features/spec_context/doctor.py::reap(workspace_root)`, composed without the container; the reaper judges by the registry — canon, exception, manifest — never by liveness.
- A fix invents no approval, task completion, evidence, disposition or operator decision; it regenerates deterministic state only, and every step reports what it did or that it skipped, never aborting the pass.
- Never touched: `references/` and `.venv/`, a registered repo's source entries and its pruned `.git .venv node_modules`, entries the install ledger names and the contents of `agentic/` and `hooks/` (hash drift belongs to `public doctor`, [[public-asset-distribution]]), a zone's `AGENTS.md`, entries matching an instance exception, unexpired files, a live session's own presence record, any ledger record's content (a re-serialization changes no value), any hand-edited record (a WARNING, never a rewrite).
