## The command

- `dadaia doctor` is the one instance validator; `dadaia public doctor` (library vs projection) is the only other doctor and touches no instance file ([[public-asset-distribution]]).
- Three sections run in fixed order: `workspace` (root, harness dirs, `.dadaia/` zones, ALIVE repo trees, installed git hooks), `specs` (the rules over one `specs/` tree), `ledgers` (the backlog document, the ADR ledger and the skill-script ledgers).
- One rule record, `dadaia_workspace/core/doctor_rules.py` (`Rule`: codes, section, run, fix, fix_help — a shell line, or a workspace-CLI argv that its one render site, `rule_fix`, spells through `fix_line` from the doctored workspace, [[sdd-gate-v3]]); `dadaia_workspace/cli/commands/doctor.py` is the only place the sections meet. A run is its findings and its exit code — there is no score. A document any rule of any section reads that is not UTF-8 ends that rule and is one `SPEC-DOC-002` error per path across the run, its fix the `Agent action:` to re-encode the failing line as UTF-8 in place, every other line kept (a shipped library file's fix is the workspace's `init`).
- A printed finding is one line `<CODE> <verdict> <message>`: `canon|operator|reaped|slop|expired|missing` for the walk, `error|warning|info` for `specs` and `ledgers`; canonical entries are not printed.
- Every error-class finding carries one fix line, printed under it, as is any other finding's fix: with real values, in one of the three forms — `fix: <command>`, `fix: Agent action: <one act>` for an act an agent performs that no single command does, or `fix: Operator action: <one act>` only for an act the law reserves to the operator (an ADR acceptance, a secret, a `.dadaiaignore` or PROTECTED edit, a named ruling, an act outside agent reach); no finding description embeds a CLI command of its own; exit 1 on any error-class finding in any section.
- `--json` emits `{"specs_dir", "sections": {<name>: {"findings": [...]}}, "fixed"}`, a finding carrying any machine-readable keys its rule adds; `--quiet` prints only what `--fix` did; `--redact` masks every foreign context name and repo slug ([[context-management]]).
- The `specs`/`ledgers` tree resolves from `--context <name>`, `--specs-dir <path>`, else the bound context; with none, those sections are empty and `workspace` still runs. A named context absent from the registry exits 1 with `Error: Context '<name>' not found.` and `fix: <cli> context list`, running no check; a stale ambient bind counts as no bind. A context whose `specs/` is not stamped at the canonical version has its `specs` onboarding step (level 3a) pending: its `specs`/`ledgers` sections are empty, and the `ONBOARDING` finding names `specs init`. An explicit `--specs-dir` that holds no tree (absent, or a path that is not a directory) is reported as one `SPECS-ABSENT` error whose fix is `state()`'s, with the `specs` and `ledgers` sections otherwise empty: an absent path's fix is `specs init`, and a non-directory is its own kind, `file`, whose fix is `Agent action: move <path> aside, it is not a directory`. A symlinked `--specs-dir` is refused, exit 1, with one fix line pointing it at the real directory. With no instance around (CI over a checkout) `workspace` is empty and an explicit `--specs-dir` tree still gets its two sections; any other run outside a workspace exits 1 with the one workspace-not-found error ([[workspace-init]]). `--public-dir` enables template drift checks; the backlog anchors derive from the repo's git-tracked paths, with no flag.
- The CI job runs `dadaia doctor --specs-dir specs` over the checked-out tree, through `scripts/ci.py doctor`, and the library's `verify:` line runs the same `doctor` job, so a job merge refuses a doctor error ([[QUALITY]], [[worktrees]]).
- `dadaia reconcile` refuses, exit 1, before any projection when `.dadaia/` or `.dadaia/agentic/` is not owned by or writable for the current user, naming the path, its owner and the `chown` repair (a host with no process uid, Windows, skips the check); an elevated run's leftovers would otherwise break the projection mid-transaction.

## The `workspace` section

- The walk covers the root, `.agents` plus each registered harness's projection directory, the `.dadaia/` top level, the first level of `repos/` and `worktrees/`, the top of every ALIVE repo (main plus associated) — only the scoped context's (`--context` or the bound one) when a run is scoped, the reaper included — the closed-canon zones and the TTL zones; the operator zones (`mcps/`, `references/`) and `.venv/` are never walked, `reports/` is never reaped, and a symlink is never followed.
- Every filesystem act of the walk and the reaper goes through `dadaia_workspace/features/spec_context/sweep.py`: a vanished entry is absent, a location outside the workspace is skipped, an `OSError` is one `skipped` action; a refusal is a typed value, falsy like a no-op, never told by its wording, so only an act that happened reads as success to the hold, `specs upgrade` and `context dead`; a delete is judged by its outcome — a surviving target is refused naming the first recorded failure, and only a permission failure adds the owner and the `Operator action:` ([[context-management]], [[specs-migration]]).
- Verdicts: `canon`, `operator` (named in `.dadaiaignore`), `slop`, `expired` (older than the zone's TTL), `missing` (level-1 core absent: an init/install zone, the harness profile, `.dadaiaignore` or `prompt.md`), `reaped` (held in `reaped/`, listed with days left).
- A TTL zone is walked once, each entry judged by its own `lstat` and never descended below its zone depth (`tmp/<agent>/<YYYYMMDD>`, `handoff/<ctx>/<file>`, `reaped/<YYYYMMDD>/<top>`); a shallower directory whose entries all expired is one entry; an expired entry is one `expired` finding, taken whole by its zone's class — an output zone's entry (a handoff, which may be an unseen no-operator bug proposal) is held in `reaped/`, an ephemeral zone's (`tmp/`, `reaped/`) is deleted; a live entry is never a finding — a TTL zone reports only expired entries and `reaped/` holds.
- Canon per level is a view of `dadaia_workspace/core/workspace_layout.py` (the gate's own answer): the root law's entries, the install ledger's harness entries, the zone names, `STATES_CANON` for `states/`, `spec-contexts.json` for `dist/`, `*.json` for `sessions/`; under `repos/` the repo slugs of every registered context, under `worktrees/` those of every ALIVE context plus `AGENTS.md`, both read through `dadaia_workspace/core/context_registry.py` — an unreadable registry admits every name there, so nothing at those two levels is judged; anything else at a judged level is `slop` unless a `.dadaiaignore` pattern names it.
- `dadaia_workspace/core/context_registry.py` is the registry's one parse: an absent file, an unparseable one or any shape but one `{"contexts": [...]}` object (`{}` included) is unreadable, never empty — `REG-SCHEMA`, error-class, with `fix: Operator action: rewrite <path> as one {"contexts": [...]} object`; the `ONBOARDING` step is then withheld and every `--fix` lane acts on nothing ([[context-management]]).
- A repo tree: only a `REPO_TREE_EXCLUDED` name (`.dadaia`; tool caches are the repo's own, redirected by configuration) is a finding (`WS-repos-slop`); `.git`, `.venv` and `node_modules` end the descent, so source is never judged.
- `.dadaiaignore` at the workspace root is the operator's file of legitimate paths: one root-relative pattern per line, `*` within one segment, a trailing `/` for a directory; a `!`, `**`, absolute or `..` line is invalid, reported as slop and never fixed; the lines after a `[protected]` header are repo-relative globs the gate refuses to any file-tool write under `repos/<r>/` and under every tree root below `worktrees/<r>/` (each ancestor holding a `.git` entry, every depth when none does); one reader serves the gate and the doctor, and the gate protects the file ([[sdd-gate-v3]]).
- Missing level-1 core is one `missing` finding per entry, one stat each with no walk, and `expire()` re-creates it and rewrites none present (a dangling link counts as present): `.dadaiaignore` from the legacy `states/instance_exceptions.txt`, verbatim, else a comment-only template (the legacy file is then slop); `prompt.md` empty; each provisioned zone; the harness profile from the projection directories present ([[workspace-init]]).
- A root `.env` or `.git` is slop that `--fix` never moves (`workspace_layout.NEVER_MOVED`): credentials and repositories live outside the workspace, so the finding carries `Operator action: move <entry> out of the workspace`; the root is never a repository, so neither `.gitignore` nor `.git/` is canon there.
- An unreadable `.dadaia/sessions/` record is `WS-sessions-slop`, held by `--fix` like any slop ([[context-management]]).
- Codes are `WS-<zone>-<verdict>`. Context invariants ride the same section, error-class: `INV-4`/`INV-5`/`CTX-URL-1` (ALIVE/DEAD repo and URL coherence), `INV-6` (a repo slug owned by two contexts, report-only), `VENV-1` (venv entrypoint health, never auto-fixed), `REG-SCHEMA` (above).
- `HOOKS-DRIFT-1`: an ALIVE repo's installed `pre-push` or `reference-transaction` hook, where git runs hooks, not byte-wise its shipped script under `dadaia_workspace/public/scripts/` (`pre-push-ci-gate.sh`, `reference-transaction.sh`) — `differs`, `is absent` or `is unreadable (<reason>)`, each said as observed, read by `service.hook_state`, the installer's own decider — one finding per hook with `fix: <cli> ci install-hook --force --repo repos/<slug>`; a run scoped to a context (`--context` or the bound one) checks only that context's repos; a checkout without `.git/hooks/` is never a finding.
- `PROJECTION`: the projected instance differs from the shipped set (`public doctor`'s own verdict, e.g. a deleted `.claude/settings.json` or gate hook); one error naming every blocking line, `fix: <cli> public install`; off `--expired-only`.
- `ONBOARDING` (`info`): the next onboarding step from the one step list ([[workspace-init]]) for one context — the scoped one, else the only ALIVE one, never another — the caller's session id feeding the `bind` step, printed as `ONBOARDING info Next (<kind> step <id>): <reason>` with its `fix:` line (`--json` adds `step` and `kind`) on every run except `--expired-only`, including at zero contexts; it never changes the exit code, and a fully onboarded workspace prints none.
- `WORKTREE`: one line per worktree of the scoped context's repos, from the worktree script's rows — state (`ready`, `open`, `empty`, `orphan`, `foreign`, `unregistered`), age, commits ahead, dirty — a `ready` or `orphan` row carrying the tree's `merge` line as its fix, an unreadable list `fix: <cli> worktree list`; `info`, or `warning` past a day's age, off-canon (`orphan`, `foreign`, `unregistered`) or when the rows cannot be read; never an error, never touched by `--fix`, off `--expired-only`; SessionStart injects the same lines ([[worktrees]]).
- `SKILL-MD-LENGTH` (warning): a projected `.agents/skills/*/SKILL.md` over `behavior-map.json`'s `skill_md_line_soft`, its fix depends on where the source lives: when a repo under `repos/` holds the library source, `Agent action: add the split of <skill>/SKILL.md to a task of the open rc, then run public install`; when no repo holds it, an `Operator action:` naming the library source, since the workspace never edits a projection; off `--expired-only`.
- `--expired-only` scopes the report to expired entries and keeps the specs repairs off `--fix`; it never narrows the reaper.

## The `specs` section

- `RULES` in `dadaia_workspace/features/specs/rules.py` is the one ordered registry of check order, fix dispatch and the `--fix` help text; each run parses the tree once.
- Tree: `TREE-*` checks the canon rows of `SPECS_CANON`, and `TREE-8` alone judges placement; `TREE-5` compares every scaffolded law file (the specs root `AGENTS.md` and each `specs/<area>/AGENTS.md`) against its shipped source and `shipped-hashes.json` after the same idempotent forward rendering for the host platform — a missing one is written and a shipped version refreshed by `--fix` (both lossless), an edited one is reported with `fix: git diff --no-index -- <source> <file>` and never overwritten; the source is the shipped package's own scaffold, so a consumer repo repairs too.
- Release, judged on the live candidate under `rc-<N>/`: `SPEC-DOC-004` checks the `**Status:**` token of `SPEC.md` and `PLAN.md` when present, `SPEC-DOC-026` checks unique release ids, and `SPEC-DOC-046` warns when a release directory holds legacy `RELEASE.json` without `_RELEASE.json` and renames it by `--fix`; candidate artifact presence, the Origin line, job files and the PLAN's DAG are `release.py check`'s, re-emitted in the `ledgers` section ([[release-lifecycle]]).
- Memory: `SPEC-DOC-002`, `MEM-PLACEHOLDER-1` (an atom whose frontmatter field value is a template token, report only and never touched by `--fix`: an atom whose `slug` and `title` are both tokens carries `Agent action: fill or delete the atom`, any other `Agent action: replace the token in <field> of <path>`), `LINT-1` (one error line per violation, naming its atom: frontmatter against `memory-frontmatter-v1`, headings, wikilinks, `sources` globs, `MEM-NARRATIVE-1` history lines), `MEM-DRIFT-1` (features package map vs the live tree), `MEM-DRIFT-2` (warning: a cited `dadaia` verb or repo path that does not exist; after a command with no subcommands the next word is its argument, never a verb), `ADR-SUPERSEDED-CITATION`, `FIXED-1/2` (fixed law sections, refreshed by `--fix`: `constitution.md`'s `slop-law`, `ARCHITECTURE.md`'s `slop-code` and `QUALITY.md`'s `slop-tests`, each byte-equal to `public/data/fixed/<id>.md`; and `ARCHITECTURE.md`'s `adr-list` block, judged only where its markers exist, one line `- <id> — <title>` per accepted ADR in id order, rendered from `decisions.jsonl`). While an accepted record's `measured_by` names no `git ls-files` path, no `path::name` test or workflow-job id of such a file, and no doctor rule code, the `adr-list` block is an unfixable `FIXED-2` whose fix is an `Agent action:` naming those ids for an in-place `chore(adrs): repair` commit. `MEM-NARRATIVE-1`, `MEM-DRIFT-2`, `ADR-SUPERSEDED-CITATION` and the `LINT-1` wikilink and heading checks judge operator-authored text only, read through `core.fixed_sections.authored_text` (every fixed section blanked, line numbers kept); a generated fixed section is judged by `FIXED-1/2` alone.
- Governance and coherence: `SPEC-DOC-030` (audit shape), `SPEC-DOC-034` (missing `_archive/`, created by `--fix`), `SPEC-DOC-001`, `GITFLOW-1` (warning: the constitution's `gitflow:` block absent or malformed, `fix: <cli> specs init --specs-dir <specs>`, see [[specs-migration]]).

## The `ledgers` section

- `BL-SCHEMA`, `BL-CONFLICT` over `BACKLOG.json` (`dadaia_workspace/features/backlog/doctor.py`); `LEDGER-ADR-SCHEMA` over `decisions.jsonl` against `decision-record-v1` (an `accepted` record carries the operator's `ruling` words; every record from id 0247 on carries two or more `options`, each a name, trade-off and rejection reason), and only a record carrying a `ruling` (or a rejected one) may name an accepted id in `supersedes` or `amends`; its fix an `Agent action:` to revert the commit that introduced the line (the `git log -L` that finds it is named), or delete it while still uncommitted, then redo it as an ADR commit.
- Each record ledger script (`bugs.py`, `backlog.py`, `release.py`, `audit.py`) runs its own `check --specs <dir> --json`; error and warning records re-emit as `LEDGER-<NAME>-SCHEMA`, while informational trace rows remain on the owner script's direct JSON surface. A record without a fix means an older install (`<cli> public install`); a script that exits with no JSON is one finding carrying the script's own `fix:` line, else `<cli> public install`.
- Product-memory atoms are linted in the `specs` section through the shared `memory.py` grammar. The generated catalog pair is checked and rewritten by `memory.py` during the closure pass and `specs init` or `specs upgrade`; it is not a record ledger in the doctor's `ledgers` section.
- The doctor builds no validator for a ledger schema: where it reads a ledger itself (the backlog anchors, the ADR ledger) it goes through the scripts' own reader and schema engine, `_ledger.py`, loaded from the packaged `dd-bug-resolution` skill script itself by `core/skill_owner.load_owner`, one module object and no copy; it repairs no ledger.

## The reaper

- `--fix` runs one lane: `expire()` first — seed missing level-1 core, delete stale session records, take each TTL-expired entry by its zone's class — then move every `slop` entry, then move a DEAD context's leftover repo (`INV-5`); then, unless `--expired-only`, the specs fixes (`TREE-4`, `TREE-5`, `FIXED-1/2`, `SPEC-DOC-034`); a non-canon specs path (`TREE-8`) is reported, never removed.
- Nothing is deleted directly: slop moves to `.dadaia/reaped/<YYYYMMDD>/<workspace-relative-path>` (7-day TTL from the move); deletion happens only at a TTL expiry — an ephemeral zone's entry or a stale session record.
- `expire()` is the SessionStart lane (`dadaia doctor --fix --expired-only --quiet` from each harness's runtime config) and `--fix`'s first step, never run on a tool call; it judges by registry, never by liveness.
- A fix invents no approval, completion, evidence or disposition, and every step reports what it did or skipped.
- A linked git worktree — a directory whose `.git` file names a gitdir under `<common>/worktrees/`, never a submodule's — is skipped, with any path inside or above one, and an expired entry holding one is reported by its `WORKTREE` `foreign` row, not as `expired`; a read-only entry is made owner-writable and retried, so the reaper deletes what it owns; an expired entry still holding something another account owns is skipped with a line naming that owner and `Operator action: remove <path>`, and once the operator removes it `--fix` clears the finding.
- Never touched: the operator zones, `.venv/`, anything below the first level of `repos/` and `worktrees/` (a slop entry there holding a linked worktree is skipped), repo source, install-ledger entries, `agentic/` and `hooks/` contents (drift belongs to `public doctor`), a zone's `AGENTS.md`, `.dadaiaignore` matches, unexpired files.
