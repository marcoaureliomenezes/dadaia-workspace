sdd-gate-v3

Asset: .dadaia/scripts/sdd-spec-gate.sh · Hook tipo: PreToolUse · Closure: sdd-release-lifecycle-v1

Propósito

PreToolUse hook bash que intercepta toda invocação de Write/Edit/MultiEdit (Claude Code, Codex e equivalentes) e decide allow ou block com base em três regras em camadas: (A) atomicidade do memory — bloqueia edits em memory/*.html e memory/product/**/*.html a menos que releases/ACTIVE.md tenha phase: CLOSURE; (B) archive read-only — bloqueia qualquer write em specs/_archive/**; (C) production paths — exige que exista pelo menos uma task [-] em specs/releases/<active-release>/TASKS.md (ou em legacy features/*/TASKS.md quando SDD_LEGACY_FEATURES=1).

Fail-open: qualquer erro interno → allow (nunca bloqueia trabalho legítimo por crash).

Fluxo de uso

  1. Agente invoca uma tool de escrita (ex. Write em dadaia_workspace/foo.py).
  2. Claude Code (ou Codex/OpenCode) executa o hook sdd-spec-gate.sh passando JSON em stdin com tool_name + file_path.
  3. O gate resolve WORKSPACE_ROOT, PRIMARY_SLUG, PRIMARY_SPECS a partir de primary_context.json; lê releases/ACTIVE.md para descobrir release e phase atuais.
  4. Aplica regras A, B, C nessa ordem. A primeira regra que decida block-or-allow encerra o gate.
  5. Allow → exit 0 (silencioso); Block → STDOUT JSON {"decision":"block","reason":"..."} com mensagem orientada.
  6. Logs em /tmp/sdd-gate.log registram cada decisão com timestamp, tool, path, release-id e motivo.

    participant T as Tool Write/Edit
    participant H as Hook runtime
    participant G as sdd-spec-gate.sh v3
    participant A as releases/ACTIVE.md
    participant K as releases/<id>/TASKS.md
    T->>H: file_path = /path/to/file
    H->>G: stdin JSON
    G->>G: resolve PRIMARY_SPECS, ACTIVE_RELEASE, ACTIVE_PHASE
    alt path matches memory/**.html or memory/product/**.html
        G->>A: read phase
        alt phase = CLOSURE
            G-->>H: exit 0 (allow)
        else
            G-->>H: {block: memory atômico}
        end
    else path matches _archive/**
        G-->>H: {block: archive read-only}
    else path is meta (TASKS/PLAN/SPEC/CLOSURE/ACTIVE/backlog)
        G-->>H: exit 0 (allow meta-edit)
    else path is production
        G->>K: grep [-] marker
        alt task [-] encontrada
            G-->>H: exit 0 (allow)
        else
            G-->>H: {block: nenhuma task [-]}
        end
    end

Trigger típico

Automaticamente invocado a cada Write/Edit/MultiEdit em sessões de agente. Operador raramente interage com ele diretamente — só quando recebe um {"decision":"block"} que precisa ser entendido e resolvido.

Diferencial

Sem este gate, agentes podem escrever em qualquer lugar a qualquer momento — memory vira changelog, archive ganha edits acidentais, código de produção é editado sem rastreabilidade (qual task autorizou?). O gate é a camada mecânica do tripé de atomicidade do memory (junto com o contrato no agente product-engineer e o doctor post-hoc). É o que torna o modelo release-lifecycle observável e enforceável, não apenas documentado.

Estado runtime tocado

  • Read-only: primary_context.json, releases/ACTIVE.md, todos os TASKS.md sob specs/.
  • Write: /tmp/sdd-gate.log (append-only audit log).
  • Saída: STDOUT JSON quando bloqueia; exit 0 (silencioso) quando permite.

Dependências

  • Depende de context-management (primary_context.json).
  • Depende de agent-orchestration indiretamente (releases ativas geradas pelo product-engineer durante orchestration).
  • Projetado para .dadaia/scripts/ via public-asset-distribution.
  • Variáveis de ambiente: WORKSPACE_ROOT (override), DADAIA_CONTEXT (override de primary), SDD_LEGACY_FEATURES (habilita fallback para features/*).
