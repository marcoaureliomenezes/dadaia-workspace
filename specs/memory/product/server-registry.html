server-registry

CLI surface: interno (sem CLI direta nesta versão) · Closure: sdd-release-lifecycle-v1

Propósito

Registry interno de portas (range 3000-3999) associadas a projetos, com TTL e PID tracking. Previne conflito de portas entre dev servers spawnados em paralelo por agentes diferentes (ex. redacted-slug-trex em 3001, redacted-slug em 3002) e permite a outras sessões descobrir a URL ativa de um projeto sem hardcoding.

Sweeper automático expira entradas com TTL vencido ou cujo PID não está mais vivo, evitando vazamento de slots.

Fluxo de uso

  1. Um agente ou script spawna um dev server e registra a porta: register(port=3001, project="redacted-slug-trex", pid=os.getpid(), ttl_hours=8).
  2. Outras sessões consultam: get(port=3001) → PortEntry(url="http://localhost:3001", project, pid, expires_at).
  3. Antes de spawnar nova porta: next() retorna a próxima livre no range.
  4. Sweeper roda periodicamente removendo entradas com PID morto ou TTL expirado.

A versão atual não expõe CLI dedicada — uso é via API Python interna. Uma feature candidata em backlog/candidates.md (dev-server-registry) prevê CLI completa.

Trigger típico

Quando agentes ou scripts spawn dev servers locais e precisam coordenar para não colidir em porta.

Diferencial

Sem o registry, agentes paralelos sobreescreveriam portas uns dos outros — bug não-determinístico e difícil de diagnosticar. TTL + PID tracking evita slot leak quando processos morrem inesperadamente.

Estado runtime tocado

  • .dadaia/states/server_registry.json — array de PortEntry com TTL+PID

Dependências

  • Standalone — não depende de outras features além da estrutura criada por workspace-init.
  • Há candidata dev-server-registry em backlog/candidates.md para evolução desta feature com CLI completa + dashboard web.
