Product Memory — dadaia-workspace

Última atualização: 2026-05-30 · Closure: spec-context-tree-v2

Visão atômica

dadaia-workspace é a CLI e biblioteca que gerencia o multi-repo workspace do operador como um Spec Context Project agentic-native: organiza repositórios, ativa contexto, propaga assets canônicos para múltiplas tools (Claude Code, Codex, OpenCode, agents nativos) e enforça SDD release-based via gate hook.

O produto resolve dois problemas: (a) fragmentação entre tools agentic — cada uma com seu formato de agentes, skills, hooks — e (b) ausência de um pipeline observável SDD → implementação, com gate que impede edição em produção sem release aprovada e task [-] ativa.

Usuários

  • Operador (humano único) — orquestra trabalho entre 20 agentes em topologia de 3 tiers (Sonnet 4.6 default; Haiku 4.5 para researcher; Opus per-dispatch via DADAIA_MODEL_OVERRIDE=opus), ativa contextos, aprova specs, decide trade-offs em sessões grill-me normalmente via project-manager.
  • Tier 1 — orquestradores (com tool Agent): project-manager (intake + dispatch de workflows), project-auditor (drift detection + auditoria).
  • Tier 2 — curator (sem tool Agent): product-engineer autor de SPEC/PLAN/TASKS/CLOSURE e guardião exclusivo de specs/memory/*.html em phase CLOSURE.
  • Tier 3 — leaf specialists (17, sem tool Agent): ai-engineer, backend-engineer, code-reviewer, data-analyst, data-engineer, design-specialist, devops-engineer, frontend-engineer, game-designer, game-developer, game-tester, qa-engineer, researcher, security-reviewer, software-architect, software-engineer-node, software-engineer-python. Consumem specs, implementam/auditam dentro do escopo, geram reports HTML.
  • Hooks/gate — PreToolUse sdd-spec-gate.sh que bloqueia Write/Edit em produção sem task [-] e atomicidade de memory.

Catálogo de features

Cada feature em produção tem seu próprio HTML descritivo. Ordem reflete relevância no dia-a-dia do operador (1 = mais usada). Para detalhe funcional — fluxo de uso, trigger, diferencial — clique no nome.

  1. workspace-init— porta de entrada; cria .dadaia/, .venv, hooks e estrutura idempotente.
  2. context-management— multi-context lifecycle (criar, ativar, promover, desativar, deletar) com primary context tracking; scaffold canonical tree v2 (backlog/, bugs/, releases/, memory HTML, AGENTS.md); CLIs dadaia release new, dadaia backlog new, dadaia bug new, dadaia memory product add, dadaia migrate tree-v2.
  3. agent-orchestration— DAG runner que dispatcha agentes especialistas (cli/claude/codex/opencode) com parallel_groups + gates. Two-tier PM router: Tier-1 — 7 engine-backed workflows (spec-refinement, cross-cutting-feature, onboarding-new-repo, hotfix-release, game-dev-cycle, audit-cycle, code-review-fan-out) invocados via dadaia orchestrate run; Tier-2 — 13 PM Playbooks compostos inline na skill project-orchestration (file-iff-X rule determina o tier). Operador fornece somente demanda em linguagem natural; PM deriva tier, reserva task_ids, emite intake report. Topologia de 20 agentes em 3 tiers (2 orquestradores PM/auditor; curator PE; 17 leaf specialists). Model default claude-sonnet-4-6 nos 20; researcher em Haiku 4.5; escalação a Opus via DADAIA_MODEL_OVERRIDE=opus per-dispatch (ADR-X4). Emission contract sidecar-first handoff-v1.1 (ADR-X5); HTML apenas sob solicitação explícita ou next_handoff.agent == "human". Dispatch-to-researcher canônico em phases evidence-heavy (ADR-X6); frontend-design plugin restrito a frontend-engineer + design-specialist via rule plugin-scope.md (ADR-X7). Path-scope gate enforça paths.write_allowlist de cada agente em runtime. Consistência router↔artefatos garantida por invariante D-OC-1 (bidirectional) no dadaia specs doctor. Domínios cobertos: data engineering, business intelligence, AI-entity authoring.
  4. public-asset-distribution— canonical → .dadaia/agentic/ → projeções multi-tool (.claude/, .codex/, .opencode/, .agents/).
  5. workspace-doctor— diagnóstico + repair de invariantes do workspace state com --fix opcional.
  6. specs-doctor— 19 checks estruturais SDD: 12 SPEC-DOC (memory HTML atômico, ACTIVE.md, CLOSURE evidence triples, broken images, Mermaid script, D-OC-1 bidirectional) + 7 TREE-1..7 (canonical tree v2 shape: foundation depreciada, root SPEC.md depreciado, product/index.html, backlog/bugs/releases dirs, AGENTS.md, release artifacts, bug frontmatter). --fix auto-repara TREE-3/4; migration guard para TREE-1/2.
  7. sdd-gate-v3— hook PreToolUse que enforça atomicidade do memory, archive read-only e exige task [-] ativa para edits de produção.
  8. sdd-hotfix-track— SemVer vMAJOR.MINOR.PATCH em specs/releases/ com PATCH≥1 reservado para hotfix release (fluxo condensado, origem via ## Hotfixes pendentes do backlog).
  9. agent-sdd-alignment— agentes, skills, workflows e templates SDD release-aware (specs/releases/<active>/ como primary; features/<feat>/ apenas Legacy compat) + dadaia specs init + doctor SPEC-DOC-003/012 + CI specs-doctor.
  10. panel— superfície de controle local em http://127.0.0.1:4999/ via dadaia panel; 7 tabs (Projects / Agents / Workflows / Sessions / Reports / Academy / Servers) com agent cards brand-identity (mint/sage/warm palette, WCAG AA badges), 12 workflow cards + DAG SVG server-rendered, tabela Sessions 8 colunas com per-cell min-width (CSS class selectors, floor 792px) + overflow-x:auto + Codex placeholder '—' em PROJECT, theme switcher 3 paletas, per-tab runtime toggle Claude/Codex, memory HTML via two-route proxy com memory.css brand-identity, Bearer token + CSP/nosniff; loopback bypass (panel-ux-fix-v1): GET /api/* retorna 200 sem token quando bind=127.0.0.1 (loopback_bypass=True em make_handler_class()).
  11. agent-monitoring— telemetria local stdlib-only consumindo Claude Code jsonl + Codex sqlite; alimenta abas Agents e Workflows do panel; allowlist gate hardcoded preserva privacidade por construção.
  12. agent-comms— contrato handoff-v1.1 que materializa o referente schema_ref: handoff-schema-v1; schema JSON Draft 2020-12 + CLI dadaia reports validate/lint/next stdlib-only + skill dadaia-handoff-emitter declarada e invocada pelos 21 agentes da topologia (adoção completa).
  13. multi-platform-parity— Pilar 3 entre Claude Code / Codex / OpenCode: Codex [agents.<name>] blocks + [skills] table em .codex/config.toml; doctor emite [not-applicable] cyan para Codex workflows; cleanup unconditional + atomic writes via _atomic_write_text.
  14. academy— sistema de cursos copy-from-template para onboarding de contribuidores e agentes.
  15. workspace-portability— export/import do workspace inteiro como tar.gz para backup ou migração entre máquinas.
  16. repos-catalog— lookup do repos.xlsx para discovery rápida de repos conhecidos com slug + URL.
  17. server-registry— registry interno de portas (3000-3999) com TTL+PID para evitar conflito entre dev servers de agentes paralelos.
  18. brand-identity— paleta canônica de 5 cores e tokens CSS do panel (release dadaia-workspace-brand-identity-v1).

Limites conhecidos

Comportamentos esperados que NÃO fazem parte do produto atual:

  • Não gerencia múltiplos workspaces simultaneamente — um workspace por instância da CLI.
  • Não substitui o controle de versão — Git permanece a fonte de verdade do histórico.
  • Não impede manualmente o operador de editar arquivos fora da CLI (gate é PreToolUse hook agentic, não filesystem permission).
  • Não faz schema migration automática de .dadaia/states/*.json — operador roda dadaia doctor --fix.
  • Não orquestra deploy de produção — apenas o pipeline interno SDD. Deploy fica em devops-engineer com GitHub Actions.
