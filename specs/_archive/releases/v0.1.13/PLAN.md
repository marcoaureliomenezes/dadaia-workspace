## Strategy

Proceed in four implementation waves aligned to the operator's requested steps:

1. Course authoring first, because it is the most complete knowledge capture and
   gives the skill refinements their source vocabulary.
2. Skill refinement second, converting the course-level model into concise
   operational protocols for `ai-engineer` and shared harness literacy.
3. Projection fixes third, because the implementation must match the refined model:
   Codex Rules are command policy, custom agents need honest sandbox boundaries, and
   workflows are reference-only unless an explicit subagent spawn happens.
4. Verification last, including public projection, focused tests, Codex rule
   validation attempt, and Academy visibility.

## Amendment — alpha-2: Codex Runtime Fidelity residuals

Three waves, strictly ordered: A1's verified facts gate the final shape of A2
(matcher form, rules semantics). End-of-alpha-2 review: qa-engineer only (ADR-3).

### A1 — Verification harness (WS-CDX-VERIFY, T-013-08)

Scripted, repeatable harness — `codex exec` against a trusted throwaway workspace
generated under `.dadaia/tmp/` (never the live instance):

- **Probe hooks** writing marker files per event (SessionStart, UserPromptSubmit,
  PreToolUse, PostToolUse) to prove each event fires and command strings exec.
- **FROZEN write attempt:** `apply_patch` against `specs/_archive/` in the
  throwaway workspace; assert the gate blocks.
- **The 3 F-1 contract points:** (a) anchored-regex matcher form
  `^(apply_patch|Edit|Write)$` vs the skill's documented bare form; (b) the
  `{"decision":"block"}` stdout envelope vs exit-code denial semantics; (c)
  shell-exec of env-prefixed command strings
  (`DADAIA_HOOK_OUTPUT=codex-json python -m ...`).
- **Config-key probes:** `approved_commands` (F-6) and `[agents."<n>"]
  config_file` (F-8) — observed behavior, not doc inference.

Outcomes are recorded as facts in `ai-harness-codex` + academy 07; the PreToolUse
matcher is aligned with the documented form if the live run shows the anchored
form misbehaves.

### A2 — Mechanical bugfix wave (WS-CDX-BUGFIX, T-013-09..11)

- `description` field through the same replacement table as the body; D-CX-4
  extended with Claude tool-name patterns (`Agent tool`, `Task tool`).
- `prefix_rule` patterns matching the mandated venv invocation form
  (`.dadaia/.venv/bin/dadaia ...`), proven by `match=` examples using the real
  form; final shape per A1's verified rules semantics.
- Stale T-35 lint deleted (or inverted to flag the dead `-python|-node` names).

All mechanical, test-backed.

### A3 — Model strategy (WS-CDX-MODEL, T-013-12)

Per-runtime tier rendering replaces MODEL_MAP prose substitution: the persona
tier table is rendered from a per-runtime registry view (Codex column carries
`model` × `model_reasoning_effort` as first-class axes), Anthropic tier-name
prose (Opus/Sonnet/Haiku) is stripped from Codex-projected bodies, and rendering
fails loudly when a mapping collapses two tiers into one id (today:
`deep`/`dispatch` → `gpt-5.5`).
