Product Memory — dadaia-workspace

Última atualização: 2026-05-16 · Closure: sdd-release-lifecycle-v1

Visão atômica

dadaia-workspace é a CLI e biblioteca que gerencia o multi-repo workspace do operador como um Spec Context Project agentic-native: organiza repositórios, ativa contexto, propaga assets canônicos para múltiplas tools (Claude Code, Codex, OpenCode, agents nativos) e enforça SDD release-based via gate hook.

O produto resolve dois problemas: (a) fragmentação entre tools agentic — cada uma com seu formato de agentes, skills, hooks — e (b) ausência de um pipeline observável SDD → implementação, com gate que impede edição em produção sem release aprovada e task [-] ativa.

Usuários

  • Operador (humano único) — orquestra trabalho entre 8+ agentes especialistas, ativa contextos, aprova specs, decide trade-offs em sessões grill-me.
  • Agentes especialistas — product-engineer, software-engineer, software-architect, devops-engineer, qa-engineer, game-developer, game-designer, game-tester, frontend-engineer, backend-engineer. Consumem specs, implementam dentro do escopo das tasks, geram reports HTML.
  • Hooks/gate — PreToolUse sdd-spec-gate.sh que bloqueia Write/Edit em produção sem task [-] e atomicidade de memory.

Capacidades atuais

  • dadaia init — inicializa estrutura .dadaia/ em workspace novo.
  • dadaia context activate <name> / dadaia context show --json — ativa Spec Context Project; primário fica em .dadaia/states/primary_context.json.
  • dadaia repos add/list/remove — gerência de repositórios sob repos/.
  • dadaia public stage / install --target all / doctor — pipeline de propagação canonical → .dadaia/agentic/ → .claude/, .codex/, .opencode/, .agents/.
  • dadaia doctor — diagnóstico estrutural do estado do workspace.
  • dadaia specs doctor — diagnóstico estrutural do SDD release-lifecycle (memory HTML, ACTIVE.md, status canônicos, CLOSURE evidence triples, broken images, Mermaid presence).
  • dadaia orchestrate — orquestração de execução agentic (parallel/sequential groups).
  • dadaia export / import — portabilidade do workspace inteiro.
  • dadaia academy — sistema interno de tutoriais.
  • Hook sdd-spec-gate.sh v3 — bloqueia: edição de specs/memory/*.html|md fora de phase CLOSURE; specs/_archive/* read-only; produção sem task [-] em release ativa.
  • SDD release lifecycle de 8 fases (Discovery → SPEC → PLAN → TASKS → Implementation → Closure → Memory Update → Archive) com memory HTML atômico como única source-of-truth do produto.

Limites conhecidos

Comportamentos esperados que NÃO fazem parte do produto atual:

  • Não gerencia múltiplos workspaces simultaneamente — um workspace por instância da CLI.
  • Não substitui o controle de versão — Git permanece a fonte de verdade do histórico.
  • Não impede manualmente o operador de editar arquivos fora da CLI (gate é PreToolUse hook, não filesystem permission).
  • Não faz schema migration automática de .dadaia/states/*.json — operador roda dadaia doctor --fix.
  • Não orquestra deploy de produção — apenas o pipeline interno SDD. Deploy fica em devops-engineer com GitHub Actions.
  • Não automatiza Phase 7 de outras release-migrações — cada repo recebe sua release dedicada quando promovido.
