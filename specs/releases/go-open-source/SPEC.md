## Objective

Make the `dadaia-workspace` library repository publicly visible on GitHub without
leaking private infrastructure details, consumer-corrupting canonical assets, junk
files, or supply-chain risks. The library is already published on PyPI
(`dadaia-workspace`, 1 000+ downloads) from the private repo
`marcoaureliomenezes/dadaia-workspace`. This release closes every blocker and governance
gap identified by four specialist audits before the visibility switch is made.

## Product deltas

This release does not ship new user-visible CLI commands or features. Its deltas are:

1. A `LICENSE` file (MIT) added to the repo root — legally required for an open-source
   project that declares MIT on PyPI.
2. `public/` canonical assets scrubbed of all operator-specific content (container names,
   VPS paths, env-var grep targets, instance-specific backlog). The assets remain
   functionally complete for any consumer; they become genuinely generic.
3. A `CONTRIBUTING.md` explaining: what `specs/` is, that `.claude/` etc. are generated
   by `dadaia public install` and must not be committed, and that Node.js is only needed
   for E2E Playwright tests.
4. A license badge added to `README.md`.

### Defense-in-depth (recurrence prevention)

Per researcher root-cause report, the leak was historical (pre-guardrail commits,
2026-05-16–19) plus incomplete cleanup plus a `.gitignore` gap. Three defense layers to
close the remaining gaps:

**D1 — Production guard in `public_assets.py`:** make `dadaia public install`/`init`
refuse to scaffold into a directory that contains the lib's own `pyproject.toml` with
`name = "dadaia-workspace"`, regardless of manifest presence. This closes the
`_is_self_repo` manifest-dependency gap.

**D2 — Root `tests/conftest.py` autouse sandbox fixture:** there is currently no
`conftest.py` in `tests/`. Add one that (a) chdirs every test to a `tmp_path`-derived
sandbox by default, and/or (b) asserts no new entries appear at the repo root after each
test. This backstops against a future un-sandboxed test silently re-introducing the leak.

**D3 — CI drift check job:** add a lightweight job to `.github/workflows/ci.yml` that
fails if `git ls-files` ever matches `^\.(claude|agents|codex|opencode)/` or
`^\.dadaia/(agentic|scripts|states|reports)/`. Job name: `repo-hygiene`.

## Dependencies and risks

**R1 — Full gitleaks history scan (813 commits):** if real secrets are found in history,
a `git filter-repo`/BFG clean is required before going public. This is the highest-risk
unknown. Mitigated by: (a) no live credentials found in the bounded 200-commit scan,
(b) the repo has been private throughout its history, so any historical leak has not
been world-readable to date.

**R2 — PyPI Trusted Publishing not yet confirmed:** if the `pypi` OIDC environment is
not configured on pypi.org, the first release after going public will fail the publish
step. Non-blocking for the visibility flip but should be resolved before any version bump.

**R3 — `dadaia public doctor` drift after `public/` asset edits:** editing
`public/skills/dadaia-grill-me/SKILL.md` and `public/scripts/sdd-spec-gate.sh` requires
re-staging and re-propagating to all runtime projections. Forgetting this step will leave
the projected assets inconsistent with the source. Mitigated by AC-GOS-05.

**R4 — Branch protection race window:** the window between flipping visibility and
applying branch protection is a brief exposure where anyone who discovers the repo could
attempt to fork and submit a PR. Mitigation: apply branch protection within minutes of
the visibility flip (GOV-7 step 9).

**OQ-01 — RESOLVED: keep `opencode.json` tracked.**

Content verified by operator: `$schema` (opencode.ai/config.json), `instructions:

permissive default that consumers inherit; consider tightening in a future release.
T-GOS-A1 must NOT remove or gitignore `opencode.json`.

**OQ-02 — RESOLVED: add header note to root `AGENTS.md` (Option 2).**
Decision: add a header note to the root `AGENTS.md` that (a) clarifies the file is the
workspace agent-rules document and NOT a human contribution guide (direct humans to
`CONTRIBUTING.md`), and (b) makes clear that contributors needing to add a rule must
scope it to a repo-local rule file and must NOT edit the canonical/global workspace rule.
Critical ownership constraint: root `AGENTS.md` is lib-originated, fanned out from

edited in place. The implementation is: edit the SOURCE at
`dadaia_workspace/public/data/AGENTS.md`, then re-stage + re-install (folds into
T-GOS-B3 propagation). New task T-GOS-B4 assigned to ai-engineer.

**OQ-03 — RESOLVED: `enforce_admins = true`.**
Decision: branch protection ruleset on `main` uses `enforce_admins: true`. The owner is
also bound by the PR/review rules — the strongest open-source trust signal. The `gh api`
branch-protection call in T-GOS-OPS1 must set `enforce_admins: true`. AC-GOS-12 updated
accordingly.
