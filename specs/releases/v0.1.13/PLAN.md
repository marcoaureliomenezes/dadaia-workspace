## Strategy

Proceed in four implementation waves aligned to the operator's requested steps:

1. Course authoring first, because it is the most complete knowledge capture and
   gives the skill refinements their source vocabulary.
2. Skill refinement second, converting the course-level model into concise
   operational protocols for `ai-engineer` and shared harness literacy.
3. Projection fixes third, because the implementation must match the refined model:
   Codex Rules are command policy, custom agents need honest sandbox boundaries, and
   workflows are reference-only unless an explicit subagent spawn happens.
4. Verification last, including public projection, focused tests, Codex rule
   validation attempt, and Academy visibility.

## Risks

| Risk | Mitigation |
|---|---|
| Overstating Codex workflow automation | Repeat the official constraint: subagents spawn only when explicitly requested. |
| Course becomes a pasted docs mirror | Paraphrase, cite official sources, orient to dadaia decisions. |
| Project-local config crosses trust boundaries | Keep provider/auth/telemetry out of generated project config. |
| Projection tests accept invalid `.rules` shape | Add tests for `prefix_rule` and absence of `command_allowed`. |
| Runtime files edited directly | Use `public stage/install`; never patch `.codex/` as source. |
