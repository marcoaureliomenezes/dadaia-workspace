# Job 10 — scope follows the tree a write lands in, so no refusal rebinds a shared session (bug `subagent-bind-rebinds-the-parent-session-across-contexts`)

**Status:** Draft

Wave 3, waits on Job 4 (`workspace_layout.py`). Paths are repository-relative to `repos/dadaia-workspace/`; `P/` = `dadaia_workspace/`. Design and evidence: PLAN §1 (cause D), §2 (Job 10).

- **Structural cause.** Subagents inherit the parent's session id (`.dadaia/AGENTS.md:30`, §2), so they share one record (`P/core/session_store.py:40-49`) and one bind (`P/core/invocation.py:195-209`, `resolve_bind`). The scope refusal (`P/features/spec_context/gate_policy.py:139`) prints `context bind <owner>` (`:146`) for any session with an id; running it rewrites the one record, so every concurrent writer in the previously bound context is then refused. The bug recurs the resolved `spec-navigator-subagent-rebinds-parent`, whose fix did not touch the refusal's own fix line.
- **Operator ruling.** "Register both, rc-20 (Recommended)", chosen over "never run cross-project agents in parallel": an agent's working binding follows the tree it writes in, so no session-wide rebind is needed. Handing a write back to the main thread would serialize multi-project work, the option rejected.
- **Shape (T2).** Scope follows the tree. `evaluate` (`gate_policy.py:139`) keeps its one decider of a path's owning context (`scope` and `context_name_for_repo_slug` supply `repo`, `zone` and `owner`). A write whose target lies inside a linked worktree of this workspace (a `worktrees/<repo>/…` ancestor holding a `.git` gitfile that `workspace_layout.is_worktree_gitfile` accepts, the walk `protected_glob` already does at `workspace_layout.py:299-304`, factored once and shared) of a registered context is in scope whatever the session's bind, including no bind: opening the tree is the main thread's act and that act is the authorization. Nothing rebinds, no per-actor store or id is added, and `.dadaia/AGENTS.md:30` stays true. Every other write keeps today's rule and fix: `repos/` paths, a folder under `worktrees/<repo>/` with no gitfile, an unregistered slug, the id-less relaunch act. The Job 4 REBUILD of `is_worktree_gitfile` lands first (this job waits on it); this job reuses its result and adds only the shared walk.
