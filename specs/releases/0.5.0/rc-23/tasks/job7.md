# Job 7 — the deploy gate: `Eval gate` (FR5)

**Status:** Draft

Paths are repository-relative to `repos/dadaia-workspace/`. Design and evidence: PLAN section 1 (R05, R09), section 3 (the operator's branch-protection act) and section 5 (H7, H10). Wave 4, the last: the SPEC ranks the gate after the features, and the gate reads the conclusion of the workflow that Job 6 rewrites. The job opens when Job 6 has merged.

**Contract.** `evals/scripts/gate.py HEAD_SHA` (stdlib only; `git` and `gh`, no model, no secret) lists the successful runs of `eval.yml` with one `gh api repos/$GITHUB_REPOSITORY/actions/workflows/eval.yml/runs?status=success&per_page=100` call, keeps those whose `event` is `workflow_dispatch` or `schedule`, and tries each `head_sha` E newest first. E passes when `git diff --name-only E HEAD_SHA` lists only these paths (ADR 0277 (2)): `specs/releases/<id>/_RELEASE.json`, `CHANGELOG.md`, `.release-please-manifest.json`, and `pyproject.toml` when `git diff -U0 E HEAD_SHA -- pyproject.toml` changes no line but `version = …` lines. The rule is a tree diff, because develop advances by merge commits. On a pass it prints E and the run URL and exits 0. Otherwise it exits 1 with one `fix: Agent action: …` line naming `gh workflow run eval.yml --ref feature/<id>`, where `<id>` is the name of the single `specs/releases/<id>/` directory of `HEAD_SHA` and `feature/` is the work prefix of `specs/constitution.md` `gitflow:` (read at definition: `{"work": "feature/"}`). An E the checkout does not hold is a failed candidate, never a crash.

`ci.yml` gains one job, `Eval gate`: `if: github.event_name == 'pull_request' && github.base_ref == 'main'`, `permissions` `contents: read` and `actions: read`, a checkout with `fetch-depth: 0` (the guard `ci-checkout-history` requires it), `GH_TOKEN` from `github.token` and the PR head sha passed through `env` (no `${{ }}` in the `run` body), one step `python3 evals/scripts/gate.py "$HEAD_SHA"`. No secret expression, no model CLI. A skipped job satisfies a required context, as `PR title` does on a push. `release.yml` reuses `ci.yml` through `workflow_call` on a non-PR event, so the job is skipped there. `.github/required-checks.json` gains `Eval gate`; the guard `required-checks-listed` is the test of both edits, and fails when only one lands.

**Hazards.** The release-please release PR also targets `main`; its head differs from E by the allowed set, so the same check passes it. Any commit after E that touches a path outside the set (a memory atom, a doc, a source file) invalidates E and costs a new pipeline run (PLAN section 5, H10). `gh` and `git` are present on the hosted runner; the tests use a fake `gh` first on `PATH` and a throwaway git repository.

**Definition of done (each task).** `python scripts/ci.py job` passes (about 73 s); the reached tests `python -m pytest -q tests/e2e/test_evals_gate.py` pass (an estimate of a few seconds: one git repository per row); for T3, reverting `gate.py` makes the T1 and T2 rows red again; for T4, `python scripts/guards/run.py` (21.5 s measured on the define tree) is green and lists no `unlisted-check`; the own-diff self-check of `dd-release-implementation` section 3. The test file carries its `Owner:` line and no task or AC id in a docstring or comment.
