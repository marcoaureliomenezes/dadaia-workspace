# Job 6 — the pipeline and its guard (FR1, FR2, FR6, FR8; AC4.4)

**Status:** Draft

Paths are repository-relative to `repos/dadaia-workspace/`. Design and evidence: PLAN section 1 (R01, R04), section 4 (consumers), section 5 (H2, H3, H5, H6, H9). Wave 3. The workflow and its guard are one job on purpose: `ci.py job` runs `guards --planted` at every task merge, so the guard widens first (T2) and the workflow is rewritten after it (T3 to T5), each merge green. The job opens when Jobs 3, 4 and 5 have merged and ADR 0281 is accepted (an operator act, PLAN section 3). Every task here is serial: all write the same files.

**Contract of the workflow** (SPEC FR1, FR2, FR6; the numbers in brackets are SPEC's):

- Triggers, `permissions: contents: read` and `env.CLAUDE_CODE_VERSION` are unchanged. The jobs are `prepare`, `eval` (the matrix), `aggregate` and `result`.
- `prepare`: hosted `ubuntu-24.04`, no secret, no environment. It builds the wheel once, uploads it as artifact `wheel` (path `dist/*.whl`) and outputs its sha256 (AC1.1). It reads the `E2E Python (pytest)` check run on `GITHUB_SHA` through `gh api` with `GH_TOKEN` from `github.token` and fails unless it concluded `success`; it never reruns a grader self-test (AC1.2). It sets `checks: read` at job level.
- `eval`: `needs: prepare`, `environment: evals`, `timeout-minutes: 45`, `strategy.fail-fast: false`, and six `include` rows (`claude-code` and `codex` times `t1-cold-onboarding`, `t2-block-list-bug`, `t3-discovery`), each with `harness`, `task`, `model`, `version` and `secret_name` (AC2.1, AC2.3; the key is `secret_name` because the push-gate denylist reads `secret: <NAME>` as a leaked credential). The rows: `claude-code` / `anthropic/claude-sonnet-5` / `2.1.284` / `CLAUDE_CODE_OAUTH_TOKEN`; `codex` / `openai/gpt-6.1-sol` / `0.163.0` / `CODEX_AUTH_JSON`. The Claude row's version equals `env.CLAUDE_CODE_VERSION` (the `env` context is not available in `strategy`, so the row repeats it and the guard checks the equality). The job `env` holds exactly one secret expression, `SCAN_SECRET: ${{ secrets[matrix.secret_name] }}` (a matrix job has one `env`, so naming each harness's variable there would give every leg both secrets); a Claude step exports it as `CLAUDE_CODE_OAUTH_TOKEN` with `CLAUDE_FORCE_OAUTH=1` through `$GITHUB_ENV`, and a Codex step writes it to the auth file. No other secret is read in the job, because harbor's agent env falls back to all of `os.environ` (AC2.2). Steps in order: checkout; download `wheel` and compare its sha256 with `needs.prepare.outputs.wheel_sha256` passed through `env`; install harbor 0.23.0; `preflight.py`; for Codex `render.py` into `$RUNNER_TEMP` and the 0600 auth file with `CODEX_AUTH_JSON_PATH`; write the wheel and its `requirements.txt` into each served task's `environment/lib/`; `harbor run -i <task> -a <agent> -m <model> --ak version=<version> -k 3 -n 3 -o evals/jobs/<harness>/<task>` with `--max-retries 2` and one `--retry-include` for each of `EnvironmentStartTimeoutError`, `SandboxBuildFailedError`, `SandboxLikelyOutOfMemoryError`, `VerifierTimeoutError`, `ApiRateLimitError`, `ApiOverloadedError`, `ApiInternalServerError`, `ApiConnectionError` (AC2.4; the flags `--max-retries`, `--retry-include`, `-i`, `-o`, `-k`, `-n` and `--ak` were read from `harbor run --help` of 0.23.0 at definition; the retry count is the PLAN's choice, bounded at the cost of one leg); `compare.py` in the leg with `continue-on-error`; for Codex the removal of every `agent/sessions` directory under its leg's output (`find … -path '*/agent/sessions' -prune -exec rm -rf {} +`) after it and before the scan (AC4.4); the canonical tail (`scan.py evals/jobs evals/summary.md`, the summary step, the upload of `evals/jobs/` and `evals/summary.md` under the name `jobs-<harness>-<task>`); and a last step that exits 1 when compare failed, so `gh run rerun --failed` reruns that leg alone.
- `aggregate`: `needs: eval`, `if: ${{ !cancelled() }}`, no secret, no environment. It downloads `jobs-*` with `merge-multiple` into `evals/` (each artifact is rooted at `evals/`, the common ancestor of its two paths), runs `compare.py --table evals/jobs > evals/summary.md` with `continue-on-error`, then the canonical scan line and the summary step, and exits 1 when compare failed. It reads no transcript and uploads nothing (AC4.1, AC4.7).
- `result`: `needs: [prepare, eval, aggregate]`, `if: ${{ always() }}`, one step that exits 1 unless the three results read `success` (goal 1).

**Decisions the PLAN takes where the SPEC is silent.** (1) The wheel upload is not a publish: `_publishes` ignores an `upload-artifact` whose path is exactly the wheel path, because `prepare` holds no secret and no model output; any other upload stays a publish and needs the scan before it. (2) The leg's output lives at `evals/jobs/<harness>/<task>/`, so two legs of one harness never write the same `leg.json` (an artifact merge would collide). (3) The leg fails on its own floor as well as aggregate, because `gh run rerun --failed` reruns only failed jobs and a leg that stays green on a below-floor result could never be rerun.

**Hazards.** Planted rows are anchored on literal text of today's `eval.yml` (`runs-on: ubuntu-24.04`, `      - run: pipx install poetry`, `    environment: evals\n`, the upload action line, the scan line, `cat evals/summary.md >>`); `_edit` raises `plant anchor lost` when an anchor disappears, so T3 keeps each anchor at least once or re-points the row in the same commit, and T4 and T5 re-run the guards before the commit. The first real exercise of the YAML is the run on E; a defect found there is a red-CI-loop fix, not a new gate.

**Definition of done (each task).** `python scripts/ci.py job` passes (about 73 s; `guards` 21.5 s and `guards --planted` 26.7 s of it, measured on the define tree, 219 planted rows, so about 0.12 s per added row); the reached tests `python -m pytest -q tests/scripts/guards/test_repo.py` pass (6 rows, 1.3 s measured); a RED task's new rows fail for the stated reason; for T2, reverting `repo.py` makes the T1 rows red again; no planted row is deleted or loosened (AC8.3): `git diff <base>...HEAD -- scripts/guards/repo.py` is read for removed rows, and every pre-existing row id is still present; the own-diff self-check of `dd-release-implementation` section 3. A REBUILD task commits as `refactor(<id>): REBUILD <unit> — …`. No `${{ }}` in a `run` body, no new action outside `actions/` and no new dependency.
