**The contract the tasks share** (stated once; the tests assert it with literals):

- `compare.py DIR [TASK...]` is the leg mode, and the form the existing rows already call. It reads each trial `result.json` under `DIR` (a record with `task_name`). The harness is the trial's `agent_info.name` (`claude-code` or `codex`); any other name, or none, exits 1 (AC4.3). A trial passes when its reward is at least 1 and the forged check does not zero it; a trial with a non-null `exception_info` is errored and never passes. `TASK` defaults to the three gated tasks; a leg passes its own. It writes `DIR/leg.json`, a list of `{harness, task, passes, errored, found}`, and exits 1 when a listed task has no trial or `passes` is below its floor (T1 3, T2 2, T3 2; the same for both harnesses, AC4.7).
- The forged check is a table keyed by harness name (AC4.2): for `claude-code` the transcript layout of today; for `codex` the rollouts under `agent/sessions/**/rollout-*.jsonl`, where a file is the reviewer when its first `session_meta` payload has `thread_source` `subagent` and `agent_role` `dd-code-reviewer`, and the act is a `response_item` whose payload is a `custom_tool_call` named `exec` with `verdict.py` and `--verdict` in its `input`.
- `compare.py --table DIR` is the aggregate mode: it merges every `leg.json` under `DIR` and prints a Markdown row for each (harness, task) of `claude-code` and `codex` times T1 to T3, a missing leg being a row of 0 found. Columns: harness, task, passes of 3, floor, errored, pass^3 (`C(c,3)/C(3,3)`, printed `:g`), Wilson 95% interval (`z = 1.96`, printed `[lo:.2f, hi:.2f]`), verdict; a last line `**BLOCKING**` or `**non-blocking**`. It exits 1 when any row is below its floor (AC4.6, AC4.7).
- `scan.py PATH...` reads `SCAN_SECRET` (unchanged name). When the value parses as a JSON object, every string leaf is a needle; otherwise the whole value is one. Further needles: the Anthropic token shape, an OpenAI key shape (`sk-` then 20 or more word or hyphen characters), a JWT shape (three base64url segments, the first two starting `eyJ`), and every value of `creator_user_id` and `creator_account_id` found in a scanned file. A hit exits 1 and prints the path, never the needle (AC4.5).
- `preflight.py HARNESS NAME` reads `SCAN_SECRET`. Empty exits 1; for `codex` a value that is not JSON exits 1. It prints one `::error::` line naming the harness, `NAME` and `evals/RESEED.md`, and never a value (AC1.3). It is its own script because the guard rule `scan-wrong-path` refuses any `run` that holds `scan.py` without the canonical line.

**Hazards.** The existing floor rows build their trials without `agent_info`; with the new rule they would exit 1 as unknown-harness. J3.T1 adds `agent_info.name` to the row helper: a fixture change that keeps every expected exit code, named in the commit. The tracked `SCAN_SECRET` rows stay as they are.
