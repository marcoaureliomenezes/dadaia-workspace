# Job 7 — a resolved bug's fix is its id-bearing commit (FR7, ADR 0273)

**Status:** Draft

Wave 1, waits on —. Paths are repository-relative to `repos/dadaia-workspace/`; `S/` = `dadaia_workspace/public/skills/dd-bug-resolution/scripts/`. Design and evidence: PLAN §1, §1.1, §2, §3; ADR 0273 (accepted, amends 0267).

- **Shape.** One lookup, `fix_commit` in `S/_git.py`, answers "which commit fixes bug `<id>`": one `git log --format=%H%x00%B HEAD` per repo (the main repo, then the repos beside it, as `_unreached` reads them today), newest first, the first commit whose message holds a line beginning `fix(bugs): ` or `refactor(bugs): ` whose head before ` — ` names the id (a group lists its ids separated by commas or blanks), skipping a commit that HEAD reverts. Walking newest first, a commit subjected `Revert "<S>"` adds `<S>` to the reverted set and a commit whose subject is in the set is skipped and registers nothing, so a revert of a revert makes the fix live again. A revert subject never starts `fix(bugs): `, so only a revert carrying the line `fix(bugs): <id> — revert <culprit subject>` cites a record.
- **Callers.** `bugs.py resolve` takes `fix_sha` and `fix_files` from that commit (`--fix-sha` and `fix_files(specs.parent, [sha])` at `bugs.py:171-172` go) and refuses with one fix line when there is none; `_bugs_check._unreached` is rebuilt on the lookup (a live resolved record that carries `fix_sha` and has no commit is one finding with one fix line naming `fix(bugs): <id> — …` in the commit message; the shallow-clone finding stands; `fix_sha` is never judged); `_bugs_write.by_file` reads `fix_files`, else the files of the lookup's commit. `fix_sha` is `write-once` in `bug-record-v1` (the `update --set fix_sha=` re-point goes with the `mutable-governance` class).
- **Fold (ci.py).** `_rewrite_unpublished` re-commits with a message holding every folded commit's message in order (`sha^..tip`, oldest first), after the new message when one is given. No ledger step, no re-point line, no `_cited_ids` (none is in the tree: the CI-red lane reverted them). Open point in PLAN §3 (a denylisted folded message) is ruled before T6 is dispatched.
- **Group commit.** T6 is one shape-3 commit naming both ids: `fix(bugs): worktree-sync-orphans-the-fix-sha-a-lanes-resolve-cites, push-gate-rewrite-orphans-shas-cited-in-the-range — <cause>`. It is the id-bearing commit the push-gate record needs, because both of that record's own fix commits are reverted at HEAD; the record stays `resolved` (`bugs.py` has no reopen). Its body carries the `caused_by:`/`evidence:`/`prior diffs read:`/`rebuild:` block of `dd-bug-resolution` Phase 0.
- **RED cases are built with no `--fix-sha` and no `resolve`** (red for the contract, not for an argument error): the test writes the ledger line itself with the pre-rewrite sha as `fix_sha` and the commit message `fix(bugs): <id> — …`, so today's check refuses it as unreached and the new check accepts it.
- **Archive (T1).** The reader that decides is the new lookup, which does not exist yet; the ids come from a scratch script under `.dadaia/tmp/` that, for every live resolved record carrying `fix_sha`, reads `git show -s --format=%B <fix_sha>` and keeps the record when no line beginning `fix(bugs): ` or `refactor(bugs): ` names its id before ` — `. At the wt-rc head `36a50c315` it prints 30 ids (the SPEC's 26 task-fixed plus the revert-resolved one were counted at `06ca6c045`; the job body names the count read at its base). Push-gate record `push-gate-rewrite-orphans-shas-cited-in-the-range` is not archived: its message names it, HEAD reverts the commit, and T6 cures it. The verb is `bugs.py archive <ids>` (it exists; no new reader, no new verb).
- **Contract tests that stay green, unloosened:** the check partitions of `unreached-check-refuses-a-shallow-clone-that-holds-every-fix-sha` and `unreached-fix-sha-judges-only-the-main-repo` (a fix in a repo beside the main one is clean; a shallow clone is one finding for the cut), and `test_the_sha_grammar_and_the_record_schema_agree_on_a_64_hex_fix_sha`.
