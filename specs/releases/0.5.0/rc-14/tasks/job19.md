Wave 5, with Jobs 18 and 20; waits on no FR19 job. The tool Jobs 21 to 24 prove every deletion with, and the readout every later review carries. This repository's own pipeline: it never ships and no gate, test or hook reads its output as pass or fail.
- **Why a new script (ladder).** The three existing Python mutation tools were inspected (PLAN §1.6): none scopes to a diff's lines with a per-line cap and a per-test kill list, so the first rung of the ruling fails and the stdlib mutator is the second. It adds no dependency; `pytest-cov` is already in the dev group.
- **Branch coverage stays in the readout (ruling).** The baseline run carries `--cov-branch` on the command line only; `pyproject.toml` `[tool.coverage.run]` is untouched, so the CI `contract-coverage` job (`--cov-fail-under=80`, no branch data) and its number do not move.
- **Selection by running the other script.** `mutate.py` runs `impact.py` (pre-review item 2: a component reaches another by running its entry point); `impact.py` stays the one decider of which tests a file reaches (`ci.py --changed` is its other caller, unchanged).
- **Consumers.** `tests/scripts/test_impact.py` (the existing cases stay green: no path argument means today's working-tree read); `tests/infrastructure/test_privacy_check.py` (the wheel and `public/**` hold no `mutate`: `scripts/` is outside the package); mypy `--strict` and ruff run over `scripts/` in `ci.py job`; `QUALITY.md:48` ("Mutation evidence is operator tooling, outside the repo") is the Reconciliation's; the removed `mutation-baseline` wiring (4 bug records) left no file: `git grep -nE "mutmut|cosmic" -- . ':!specs'` prints the same 2 hits (a changelog line, a memory-lint fixture string) before and after.
- **Order:** T1, T2, T3, T4 (red, green, red, green) then T5. `T1/T3` share the test file and `T2/T4` the script (ordered pairs). At most one agent runs the planted-repo tests at a time (they spawn git and pytest).
- **Sweep lines:** `git grep -n "mutate\.py" -- dadaia_workspace pyproject.toml` (0 hits, before and after: `packages = [{include = "dadaia_workspace"}]` keeps `scripts/` out of the wheel by construction); the wheel listing count; `git grep -c "CAP" -- scripts/mutate.py` (one definition).
- Docstring law for every task (PLAN, FR19 conventions): a docstring or comment a task writes or moves states only its unit's contract and carries no id of the grammar there. The sweep line of that section is quoted before and after in each commit body.
- Pre-review checklist, `PASS` or `N/A — reason` per item: (1) one reader per rule: changed lines parsed once in `mutate.py`, test selection owned by `impact.py` (2) no cross-component import: `mutate.py` runs `impact.py` and pytest as processes (3) the sweep lines above (4) platform facts: paths through `pathlib`, the interpreter is `sys.executable`; no os branch (5) net lines: scripts +~220 and tests +~140 — an ADD no unit can carry (`today` is none); nothing else grows
