# Job 23 — policy leaves pytest, part 1: shipped text, entities, projection and the CLI surface become guards (FR19)

**Status:** Draft

Wave 7, with Jobs 22 and 24 (disjoint by file, checked); waits on Job 19 and Job 21. Policy — a pytest case that asserts the wording of a law, skill or doc, or reads a tracked repo file outside its own fixtures — leaves pytest. This job takes `tests/infrastructure/`, `tests/cli/`, `tests/contract/` and `tests/scripts/`: 25 test files, a pool of 880 case lines by the prototype census (PLAN §1.6; the final census is Job 26). pytest keeps behaviour only.
- **REBUILD (PLAN row).** `test_privacy_check.py` is the file with the longest ledger (the public-law pins were widened row by row across five bug fixes: `public-law-teaches-the-private-pipeline`, `sa-consumer-law-carries-library-facts`, `law-cites-commands-that-fail-from-root`, …). One guard module per theme replaces row-by-row pytest parametrization; no row is lost, each becomes a check or a plant.
- **Dispositions, not a move.** the three dispositions (PLAN, FR19 conventions) decide each case: (a) a guard or an import-linter contract already states the question — the case is deleted, the covering check and its `--planted` row named in the commit body (AC19.9); (b) a repo-policy scan — one check in the job's guard module with a plant, `python scripts/guards/run.py --planted` RED on the plant and GREEN on CONTROL; (c) a behaviour case whose input is a real repo file — the input becomes a fixture under `tests/fixtures/` or is built in `tmp_path`. A case that duplicates an import-linter contract or an existing guard is deleted and the covering check is named; moving it would create a second decider (S10).
- **Consumers (pre-mortem).** `ARCHITECTURE.md` P-17 `Measured by: pytest tests/infrastructure/test_entity_doctor.py` and `QUALITY.md:60` (the Reconciliation repoints both to the guard check ids the commit bodies name); 158 ADR records name test paths in `measured_by` (123 distinct paths): the Reconciliation census lists those whose file no longer exists and repairs each in place; `scripts/guards/slop.py` `v38` `parity:` values (T3); `tests/contract/test_docs_derived_from_memory.py` is also the reader of `llms.txt`, `docs/*.md` and the memory atoms: the guard reads the same files, so a derived-doc drift fails `ci.py guards` instead of `unit-fast`; the hotfix `orchestration-operator-only-list…` edits `test_entity_doctor.py` and `test_privacy_check.py` (merged first); `ci.py guards` runs `run.py` and `--planted` in the `job` level, so the new modules run in every job gate.

- **Importers before a deletion (PLAN, FR19 conventions).** A task that deletes or trims a test module first runs `git grep -n "from tests\.<module path>\|import <module>"` and names every importer in its commit body; a name an importer outside the task's `W:` uses stays defined, and the task returns a seam rather than editing a file it does not own.
- **Coverage floor (PLAN, FR19 conventions).** Before hand-back the job runs `python scripts/ci.py contract-coverage` (the CI gate: `--cov-fail-under=80` over `dadaia_workspace`) on its tree and quotes the total line in its last commit body. A deletion that takes the total below the floor is refused unless the kill matrix shows the uncovered lines are dead code, in which case the dead code is deleted in the same task. The coverage run is a test run: it counts in the cap of 2 agents running tests.
- Docstring law for every task (PLAN, FR19 conventions): a docstring or comment a task writes or moves states only its unit's contract and carries no id of the grammar there. The sweep line of that section is quoted before and after in each commit body.
- Pre-review checklist, `PASS` or `N/A — reason` per item: (1) one reader per rule: each policy question has one guard check (or none, when a contract already states it) (2) no cross-component import: a guard module imports only `run.py`, the stdlib and what the existing guards import (3) the sweep lines above (4) platform facts: guards read `git ls-files` paths with `/`; no literal separator in a new assert (5) net lines: tests −~1,200 planned (upper bound −880 in this job's pool plus file overhead), `scripts/guards` +~450
