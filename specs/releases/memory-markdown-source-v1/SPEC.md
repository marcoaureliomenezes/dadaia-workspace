## 1. Problem and context

The memory subsystem shipped by `memory-structured-source-v1` (closed 2026-05-31) is a
half-migrated tripling. Every memory atom exists as:

1. `<slug>.yaml` — intended structured source, JSON-Schema validated.
2. `<slug>.html` — Jinja2-rendered output, committed alongside the YAML, and also the
   thing actually consumed by the panel and by `ctx-inject.sh`.
3. `product/catalog.json` — generated by **HTML-scraping** `product/index.html`.

The v1 schema design proved lossy: only **7 of 21 atoms** use clean structured YAML
fields; the remaining **14** (architecture, agent-orchestration, panel,
context-management, tech-stack, sdd-gate-v3, specs-doctor, and more) fall back to a
`raw_html_sections` escape hatch — raw escaped HTML stuffed inside a YAML scalar. This
defeats the "atomicity-as-schema" premise for the majority of atoms.

Consequences:
- Doctor's check #8 (forbidden changelog/history headings) falls back to grepping inside
  the `raw_html_sections` escape hatch — the exact bypassable heuristic the schema was
  meant to replace (STRUCT checks + schema enforcement give no benefit for these 14).
- The v1 dogfood measured body lossiness: architecture −25% body text, tech-stack −46%.
- HTML is the wrong source format for an LLM consumer: boilerplate (`<head>`, `<style>`,
  `<script>`, attribute noise) is pure token waste. `strip-memory-html.py` was added as
  a compensating step, but it strips only some noise and must be maintained separately.
- Three parallel truths (YAML, HTML, catalog) must stay in sync. SYNC-1 doctor check
  enforces byte-identity for YAML-sourced atoms, adding CI fragility.
- The `memory-structured-source-migration-v2` backlog candidate proposed enriching the
  v1 schemas (diagram arrays, extensible sections) to achieve lossless migration — two
  independent analyses (consumer-context angle and architecture angle) converged instead
  on a fundamentally different and simpler design: Markdown is the natural source.

This release supersedes `memory-structured-source-migration-v2` entirely.

---

## 2. Objective

Markdown-with-YAML-frontmatter becomes the **single source of truth** for all memory
atoms. Agents read `.md` directly (no strip pass needed). HTML becomes ephemeral
panel-rendered output (rendered in-memory at serve time, never written to disk). The
catalog is generated from frontmatter (no HTML scraping). Atomicity is enforced by a
heading-allowlist lint, not a body schema.

## 3. Product deltas

### 3.1 New source format

- `specs/memory/*.md` + `specs/memory/product/*.md` replace the YAML + HTML files.
- **Frontmatter** (strict, `additionalProperties: false`): `slug`, `title`,
  `category` (`core | product | ops`), `tldr` (one sentence), `summary` (one to two
  sentences), `tags[]`, `agent_tier` (`inject | self-pull`), `token_estimate`,
  `last_updated`, `release_origin`.
  - Dropped vs v1 YAML schema: `version`, `status`, `schema_version` (those belong in
    release artifacts, not living atoms).
- **Body**: Markdown, shape-validated by a `##` heading allowlist. Content is
  unconstrained within each section. The allowlist is the union of canonical PT
  section names currently used across the 21 atoms: `Propósito`, `Fluxo de uso`,
  `Trigger típico`, `Diferencial`, `Estado runtime tocado`, `Dependências`, plus
  any additional headings already present in the corpus.
  - `## Changelog`, `## Histórico`, `## History`, `## Versions` are **explicitly
    forbidden** in the allowlist. This is a deliberate lock — atomicity contract in
    `specs/memory/AGENTS.md §3` prohibits changelog/history sections. Any ai-engineer
    suggestion to add these is overridden here.
- Cross-atom links: `[[slug]]` wikilinks, lint-validated to resolve. Panel converts to
  anchors at render time. Agents read slug as plain text and self-pull
  `specs/memory/<slug>.md` by convention.
- Mermaid: plain ` ```mermaid ` fenced blocks (no escaping, no CDN script injection).

### 3.2 Read side (ctx-inject + Step-0)

- `ctx-inject.sh` repointed to read `tech-stack.md` verbatim (no strip pass needed) and
  `catalog.json` (generated from frontmatter).
- Target injection: ~2.4 K tokens (down from ~4.6 K), achieved via tighter `tldr`-first
  summaries.
- Step-0 protocol extracted from all 21 personas into a **single shared skill** (avoids
  ~400-token duplication per persona). All 21 personas updated to reference it.

### 3.3 Catalog generation

- `generate-memory-catalog.py` (new script): reads frontmatter from all `.md` files in
  `specs/memory/product/` and writes `catalog.json`.
- Catalog entry shape: `{slug, title, category, tldr, summary, tags, token_estimate,
  agent_tier}`.
- Replaces the current HTML-scraping `catalog.py` path for `.md`-format memory.

### 3.4 Panel markdown render

- Panel gains a `md → html` render path for the memory viewer.
- Implementation constraint: stdlib-only renderer **preferred** (avoids new PyPI dep);
  a lightweight dep (e.g. `mistune`) is acceptable if stdlib coverage is insufficient.
  This is Open Question OQ-1 (resolved before W2 begins).

### 3.5 Lint tooling

- `lint-memory-atoms.py` (new script): validates each atom's `.md` file:
  - Frontmatter required fields present and no extra fields (`additionalProperties`).
  - `##` headings are a subset of the allowlist.
  - No duplicate `##` headings within an atom.
  - `[[link]]` wikilinks resolve to real slugs.
  - `token_estimate` drift warning (if actual token count diverges > 20%).
  - Forbidden `## Changelog` / `## Histórico` / `## History` / `## Versions` check
    (belt-and-suspenders over the allowlist).

### 3.6 Migration tooling

- `migrate-html-to-md.py` (new script): converts the 21 existing HTML atoms to Markdown
  via `html2text` or `pandoc`, applies frontmatter scaffold, and writes `.md` files. The
  operator runs this once under PE supervision during CLOSURE (PE-only, gate-locked).

### 3.7 Born-markdown scaffold template

- `dadaia specs scaffold` (or `dadaia memory product add`) updated to generate `.md`
  atoms instead of `.yaml` atoms.

## 4. Architecture deltas

- `features/specs/catalog.py`: extend to read `.md` frontmatter (YAML block) in addition
  to (or instead of) HTML scraping; catalog.json output schema unchanged.
- `features/specs/doctor.py`:
  - **Remove** STRUCT-1..STRUCT-4 and SYNC-1 checks (YAML-sourced atom checks).
  - **Remove** YAML-absent warning.
  - **Remove** `SPEC-DOC-008` byte-identity invariant.
  - **Add** `LINT-1`: calls `lint-memory-atoms.py`; ERROR on frontmatter violations;
    WARNING on token_estimate drift.
  - **Adapt** check #8 (forbidden heading grep): now operates on `.md` body directly —
    simpler and unforgeable (no escape hatch).
  - Check #2 (memory files exist): adapt to look for `.md` files instead of `.html`.
- `features/specs/renderer.py`: **remove** the memory atom render path. Renderer becomes
  panel-only (or is removed if it served only memory atoms).
- `features/panel/views/memory.py`: adapt to serve rendered-on-the-fly HTML from `.md`
  source (inline `md → html` conversion), **not** committed HTML files. SPEC-DOC-008
  byte-identity invariant is retired.
- `public/scripts/ctx-inject.sh`: repoint from `tech-stack.html` + strip pass to
  `tech-stack.md` verbatim.
- `public/scripts/strip-memory-html.py`: **delete**.
- `public/schemas/memory/memory-*.schema.json` (4 files): **delete** (frontmatter schema
  is embedded in `lint-memory-atoms.py` or a single small JSON file; not Jinja-rendered).
- `public/templates/memory-*.html.j2` (4 files): **delete**.
- `public/scaffold/memory/*.yaml` (3 files): **delete** and replace with `.md` scaffolds.
- `dadaia memory render` CLI command: **remove** (YAML → HTML render no longer needed).
- `dadaia migrate memory-yaml` CLI command: **remove**.

## 5. Tech-stack deltas

- **Add** (D-1): `mistune~=3.0` to `pyproject.toml` runtime dependencies (pure-Python,
  zero transitive deps). Custom hooks (~100 LOC): mermaid fence, `[[wikilink]]`, sanitiser.
- **Remove** (if renderer.py memory path is eliminated and no other caller uses it):
  `jinja2` and `jsonschema` remain for other uses — only the memory-atom usage is retired;
  the deps themselves stay if used elsewhere.
- `html2text` or system `pandoc`: required at migration time (W3), not a runtime dep.

## 6. Security and operations deltas

- No new authentication surface. Panel memory viewer now renders Markdown server-side;
  the same path traversal guard (OWASP A03) in `memory.py` applies — target file must be
  under `<memory_root>`.
- HTML rendered from Markdown must be sanitised before serving (no raw `<script>` tags
  from atom content); the renderer must strip or escape inline HTML in Markdown.
- Per **D-4**, the panel renders `.md`→HTML **in-memory at serve time** — no `.html` is
  written under `specs/memory/`, so no `.gitignore` rule is needed. The 21 pre-existing
  committed `.html` atoms are deleted in W4; this structurally prevents stale render output.

## 9. Out of scope

- Body-level schema section-completeness enforcement (deliberate: give up this aspiration;
  it never held for 14/21 atoms under v1 schema, and the allowlist lint gives the same
  enforcement strength uniformly).
- Automated version bump or PyPI publish (gated to `go-open-source` capstone).
- Changes to non-memory agent personas beyond the Step-0 shared skill extraction.
- Content improvements to individual memory atoms beyond what is needed for lossless
  conversion.
- `memory-structured-source-migration-v2` feature set (enriched schemas, FIDELITY-1 gate)
  — entirely superseded by this design.
