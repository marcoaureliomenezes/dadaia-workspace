# dadaia-workspace-dev-guardrail

This rule is always active. It applies to every agent operating in this workspace.

## 1. This Workspace is a dadaia-workspace Instance

The directory at the workspace root is a **live instance** produced by the `dadaia-workspace`
Python library installed in editable mode at `repos/dadaia-workspace/`. The workspace and the
library are co-evolving: the library is developed here, and the workspace runs what the library
produces.

| Path | Role |
|------|------|
| `repos/dadaia-workspace/` | Library source code (editable install — `pip install -e`) |
| `repos/dadaia-workspace/dadaia_workspace/public/` | **Asset source of truth** — agents, rules, skills, workflows |
| `.dadaia/agentic/` | Staging area (generated by `dadaia public stage`; contains `manifest.json`) |
| `.claude/`, `.agents/`, `.codex/`, `.opencode/` | Runtime projections (generated by `dadaia public install`) |
| `AGENTS.md` (root) | Workspace rules document (fanned out from `public/data/AGENTS.md`) |
| `repos/<name>/` (other repos) | Spec Context Projects — independent domain work |

**Agents must never mistake `repos/dadaia-workspace/` for a regular Spec Context Project.**
It is the library under active development. Its `specs/` governs library releases. Its
`dadaia_workspace/public/` governs ALL agent assets across the entire workspace.

## 2. Lib-Originated Assets — Non-Edit Rule

Files that appear in `.dadaia/agentic/manifest.json` are **lib-originated**. They were generated
by `dadaia public stage` from the library source. Never edit them in-place.

**Lib-originated paths (never edit directly):**
- `.claude/agents/*.md`
- `.claude/rules/*.md`
- `.claude/skills/**`
- `.claude/workflows/*.md`
- `.agents/skills/**`
- `.codex/agents/*.toml`, `.codex/config.toml`, `.codex/hooks.json`
- `.opencode/agents/*.md`, `opencode.json`
- `AGENTS.md` (workspace root and all consumer repos)

**Correct edit workflow:**
1. Edit the source in `repos/dadaia-workspace/dadaia_workspace/public/<type>/<file>`
2. `dadaia public stage` — re-stages with updated SHA256
3. `dadaia public install --target all` — projects to all runtimes
4. `dadaia public doctor` — verify exit 0

If an agent proposes editing a lib-originated file directly, respond:

```
[LIB-GUARDRAIL] This file is lib-originated (tracked by .dadaia/agentic/manifest.json).
Edit the source at repos/dadaia-workspace/dadaia_workspace/public/<type>/<file>, then:
  dadaia public stage && dadaia public install --target all
```

## 3. Drift Detection and Repair

When the library evolves (new commits in `repos/dadaia-workspace/`), projections can drift.

**Detection:** `dadaia public doctor` — status codes:
- `[ok]` — matches source; no action
- `[drift]` — differs from source; run `dadaia public install --force --target all`
- `[missing]` — absent from projection; run `dadaia public install --target all`
- `[unsupported]` — runtime cannot project this asset type; no action
- `[not-applicable]` — logical type mismatch (e.g., workflow in Codex); no action

**Repair:**
```
dadaia public stage && dadaia public install --force --target all
dadaia public doctor  # must exit 0 before agent dispatch resumes
```

Drift repair is the responsibility of the operator or devops-engineer.
No other agent may use `--force` without explicit operator authorization.

## 4. Sub-Repo Isolation Rule

`repos/dadaia-workspace/` MUST NOT contain `.claude/rules/` or `.claude/skills/` directories.
Claude Code scans subdirectories for `.claude/` trees and loads them alongside the workspace
root `.claude/`, causing duplicate and potentially conflicting context.

The workspace root `.claude/` is the **sole authoritative** Claude Code projection.
The sub-repo's `.claude/settings.json` may remain (it configures hooks for standalone
development sessions with sub-repo-local script paths), but it must not contain rules or skills.

If `repos/dadaia-workspace/.claude/rules/` or `.claude/skills/` are present, they are stale
and must be removed immediately.

## 5. Self-Development Workflow

When evolving dadaia-workspace itself, agents follow the standard SDD lifecycle
(see `workspace-protocol`) within `repos/dadaia-workspace/specs/releases/<release-id>/`.
Additionally:

1. Edit Python source in `repos/dadaia-workspace/dadaia_workspace/`
2. For asset changes: edit `repos/dadaia-workspace/dadaia_workspace/public/<type>/`
3. Run: `cd repos/dadaia-workspace && poetry run pytest`
4. Propagate: `dadaia public stage && dadaia public install --target all`
5. Verify: `dadaia public doctor` (exit 0)
6. Commit: conventional commit tied to active task `[-]` → `[x]`

Never shortcut steps 3–5. Skipping propagation leaves projections stale and triggers
drift on next `doctor` run.

## 6. DEV Workspace Self-Reference

This workspace is a **live instance of the product being developed**. This creates a self-referential loop that every agent must keep in mind.

### The loop

```
repos/dadaia-workspace/  ← library source (editable install)
         ↓
.dadaia/.venv/           ← pip install -e points here
         ↓
.dadaia/agentic/         ← dadaia public stage reads from working tree
         ↓
.claude/ .codex/ etc.    ← dadaia public install projects to runtimes
```

### 4 invariants to keep in mind

1. **Self-referential DEV**: You are inside the workspace you are developing. Changes to the library affect the workspace you are working in.

2. **Editable install is working-tree live**: `Path(__file__)` in the installed package resolves to `repos/dadaia-workspace/dadaia_workspace/`. Any edit to Python source or `public/` files takes effect immediately — no reinstall needed. This is both the power and the danger of the DEV workspace.

3. **`dadaia public doctor` is blind to `git_HEAD ↔ working_tree` drift**: The doctor compares `working_tree_source ↔ staging ↔ projection`. It does NOT compare `git HEAD ↔ working_tree`. An uncommitted edit in `public/` will show as `[ok]` in doctor while the workspace silently runs unreviewed code. True drift check: `git diff HEAD -- dadaia_workspace/public/`

4. **Never insert consumer-specific details into `public/` assets**: `public/agents/`, `public/rules/`, `public/skills/` are the canonical source for ALL workspaces that install dadaia-workspace. Writing a project-specific path, name, or description into a canonical asset corrupts every consumer. If a fix "for this project" is needed, it belongs in a consumer-repo overlay — never in `public/`.
