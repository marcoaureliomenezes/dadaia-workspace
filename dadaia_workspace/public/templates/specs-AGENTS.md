## 3. Phase Gate

Implementation of any task must NOT begin until ALL of the following conditions are met:

1. `releases/ACTIVE.md` declares the target release and `phase: IMPLEMENTATION`.
2. `releases/<release-id>/SPEC.md` contains `**Status:** Aprovado`.
3. `releases/<release-id>/PLAN.md` contains `**Status:** Aprovado`.
4. `releases/<release-id>/TASKS.md` contains `**Status:** Aprovado`.
5. The agent flips `[ ]` → `[-]` in `TASKS.md` for the specific task and commits
   `chore(tasks): start <task-id>` BEFORE writing any production file.

The SDD gate script (`sdd-spec-gate.sh`) enforces this at the pre-tool hook level.
Gate failures are blocking — they are NOT warnings.

## 5. Memory Write-Lock Policy

`specs/memory/` files are write-locked for ALL agents EXCEPT `product-engineer`
during the CLOSURE phase of a release. During IMPLEMENTATION:

- Agents MAY read all memory files.
- Agents MUST NOT write to `specs/memory/*.html` or `specs/memory/product/*.html`.
- If an agent discovers that memory is stale, it must open a bug report via
  `dadaia bug new <slug>` describing the discrepancy and flag it in its task closure
  report. Memory updates happen at the next CLOSURE.

## 6. TASKS.md Conventions

The three task-marker states are a machine-readable contract:

| Marker | State | Meaning |
|--------|-------|---------|
| `[ ]` | OPEN | Available for pick-up |
| `[-]` | IN PROGRESS | Reserved by an active agent — do not touch |
| `[x]` | DONE | Completed, verified, committed |

Rules:
- At most one `[-]` per agent thread at a time.
- A `[-]` must be committed (`chore(tasks): start <id>`) before any production file is
  written.
- `[-]` → `[x]` transition is committed with the final implementing commit.
- If you find a stale `[-]` (no recent commit by the owning agent), stop and report to
  the operator before touching that task.

## 7. Escalation and Blocking

An agent MUST stop and escalate to `product-engineer` (and ultimately the operator) if:

- A required spec artifact (`SPEC.md`, `PLAN.md`, or `TASKS.md`) is missing or lacks
  `**Status:** Aprovado`.
- A task cannot be tested (untestable design = incomplete spec).
- A security rule (OWASP A01–A10) would be violated by the task as written.
- The agent detects write-set overlap with another `[-]` task in a concurrent session.
- `dadaia specs doctor` exits non-zero on the current tree.

Escalation format:
```
[ESCALATION] Agent: <agent-name> | Task: <task-id>
Reason: <one-sentence explanation>
Blocking artifact: <path>
Suggested resolution: <what product-engineer should do>
```

## 8. Doctor Invariants (TREE-1 through TREE-7)

`dadaia specs doctor` enforces the following tree invariants for this project.
Run `dadaia specs doctor` before every PR merge and after every scaffold operation.

| Code | Trigger | Auto-fix |
|------|---------|----------|
| TREE-1 | `specs/foundation/` exists (deprecated) | WARN-ONLY — run `dadaia migrate tree-v2` |
| TREE-2 | `specs/SPEC.md` at tree root (deprecated) | WARN-ONLY — run `dadaia migrate tree-v2` |
| TREE-3 | `memory/architecture.html`, `memory/tech-stack.html`, or `memory/product/index.html` absent | AUTO-FIX: renders from canonical Jinja template |
| TREE-4 | `backlog/`, `bugs/`, or `releases/` absent | AUTO-FIX: creates directory with `README.md` + `.gitkeep` |
| TREE-5 | `specs/AGENTS.md` absent or hash differs from canonical template | DRIFT-DETECT: warns + shows diff; does NOT overwrite |
| TREE-6 | A `releases/<id>/` directory missing a mandatory SDD artifact for its declared phase | NO AUTO-FIX: report and halt |
| TREE-7 | A `bugs/<slug>.md` missing the required `session_id` frontmatter field | NO AUTO-FIX: report and halt |

TREE-1 and TREE-2 print a loud migration prompt regardless of `--fix`:
```
[TREE MIGRATION REQUIRED] Run: dadaia migrate tree-v2
```
