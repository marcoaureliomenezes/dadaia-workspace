# Release stage — dd-grill-me

Before the SPEC, on the picked set. Inspect first; the as-is review and the bug window are inputs, not questions.

1. Per picked item: the outcome the operator wants, in one sentence, and the check that proves it.
2. For each DELETE or REBUILD row of the as-is review: confirm the behaviour that leaves, and what replaces it.
3. Per bug-window fix: keep or rebuild, and the reason.
4. Scope edge: what the release leaves out, and what waits on what.
5. Does any open question carry a technical decision past the ADR threshold? Hand it to the adr reference before the SPEC states it.

Record: the answers become the SPEC's requirements and acceptance criteria, each with the operator's words.
